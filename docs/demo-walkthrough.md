# 知源 v0.10.1：工业 FAQ 演示流程

用一套合成资料走通 **品牌与资料 → 内容任务 → 修改与审核 → 下载交付 → 记录结果**。本文是操作指南；实际通过哪些检查，以 [项目状态](project-status.md) 和对应验收记录为准。合成参数、模拟调用和内部批准不代表真实产品事实、客户验收或生产可用。

## 1. 准备独立演示环境

首次使用先按 [安装与运行](../SETUP.md) 安装依赖。以下命令在项目根目录执行，不需要聊天模型密钥，也不需要下载语义模型：

```bash
(cd frontend && npm run build)
demo_report_dir="$(mktemp -d)"
.venv/bin/python scripts/evaluate_industrial_faq.py \
  --output "$demo_report_dir/industrial-faq.json" --serve --port 8772
```

脚本使用临时 SQLite、词项检索和本地规则摘录，执行导入、核验、入库、任务、重审及权限检查，阻止对外网络连接。检查通过后保留 [合成演示页面](http://127.0.0.1:8772)；具体任务编号看终端输出的 `browser_run_id`。Ctrl+C 停止并清理临时数据库，JSON 报告和同名 `.delivery.md` 留在刚创建的临时目录。

不要把这条命令改为使用自己的 `.data` 做破坏性练习。上例为本轮结果创建独立目录；省略 `--output` 时写入 `.data/evaluations/industrial-faq-evaluation.json`，不改写历史验收文档。若命令失败，查看本轮错误和报告；不能把上次成功文件当成本次结果。端口占用时用其他空闲端口。

日常本地工作台使用 `./scripts/start.sh`，默认在 8765 端口，数据保存在 `.data/`。它默认采用语义检索；`RAG_RETRIEVAL_MODE=lexical ./scripts/start.sh` 才是显式词项模式。**检索方式与生成方式独立**：local 是规则整理与原文摘录，不是本地大语言模型。

## 2. 认清当前页面入口

| 主入口 | 当前子入口与用途 |
| --- | --- |
| 工作台 | 查看近期内容、开始任务 |
| 品牌与资料 | 品牌档案、知识资料、发现信源；「更多」包含核验笔记和原始素材 |
| 内容任务 | 创作任务、资料问答；「更多」包含备选选题 |
| 审核交付 | 稿件编辑器：正文、卡片、检查与导出 |
| 效果复盘 | 发布复盘、发布数据、试点验收 |

「设置与连接」在侧栏底部；本地模式提供模型与信源、运行诊断，团队模式另有成员、用量、账号。学习材料从 [文档导航](README.md) 进入；产品已不提供旧版「学习中心」主入口。

## 3. 核对合成品牌与资料

进入「品牌与资料 → 品牌档案」，查看「合成星桥工业设备（虚构）」的知识库、受众、禁用表述和本地生成策略。品牌要求决定表达方式，不能替代产品事实。

再从「更多 → 核验笔记」查看 `合成星桥 XP-24` 的材料，逐项找到：来源、授权声明、资料版本、原文定位、产品型号、参数和值。核验与入库是分开的动作；待核验、过期、撤销或存在有效冲突的事实不能直接作为有效依据。

`example.com` 地址只是合成定位标识，不需要访问。普通文件导入在「知识资料」中先预览、后确认入库；普通上传不会自动获得“已核验参数”的身份。详见 [工业 FAQ 练习](industrial-faq-practice.md)。

## 4. 新建一份有明确事实要求的 FAQ

在「内容任务 → 创作任务」中：

1. 选择演示品牌，模板选择「产品与服务答疑」。
2. 目标填写「合成星桥 XP-24 额定电压与额定流量答疑」，生成方式使用「本地摘录 · 无需密钥」。确认知识库来自所选品牌。
3. 展开「必须有依据的产品参数」，型号填写 `合成星桥 XP-24`；参数分两行填写 `额定电压`、`额定流量`。字段应与核验笔记一致。
4. 提交后观察准备资料、生成与检查、人工审核三个阶段。最终应等待人工审核。
5. 展开「查看依据」，逐项核对正文和卡片是否被片段支持；查看「执行详情与审核历史」和「模型调用与费用」。

必需参数是显式契约，缺少任一项应停止生成。留空只做相关资料检索，不保证目标中的每个问题都有答案；不要把检索命中或合法引用编号当成事实正确性证明。

本地摘录不产生外部聊天模型费用；调用日志数量也不等于节点数量。只有另行配置并实际使用在线模型后，才讨论真实 token 与费用；缺失值保留未知，估算不是账单。当前演示不会验证在线供应商，详见 [调用追溯说明](model-call-tracing.md)。

## 5. 完成退回、修改和重新审核

在新任务的待审状态填写一条具体意见，例如「将额定电压和额定流量分段说明，保留引用」，然后「退回修改」。

点击「修改原稿」，确认稿件编号对应原任务。编辑器的「正文」与「卡片」分别保存；修改正文后还要检查卡片是否同步。保存后点击「返回审核任务」，再「修改后重新送审」。核对当前内容与依据后点击「审核通过」。

状态应为 `rejected → awaiting_review → approved`，旧意见保留。批准后再修改正文或卡片，应使旧批准失效并回到待审。质量评分、检查清单勾选和素材下载都不会替你批准任务。

## 6. 下载交付，并查看记录边界

通过后在任务页点击「下载审核交付清单」，打开 Markdown，检查正文、出处、资料版本/定位和内容 hash。服务端会再次核对当前批准版本与引用有效性；过期、撤销或冲突资料不能靠旧批准绕过。

「查看依据」保存的是生成时材料；交付清单中注明交付时读取的资料元数据，不应误说成生成时版本。内部备注、原始引用摘录和模型配置不属于正式清单。已审核正文会原样交付，仍须人工检查是否含不应外发的信息。

PNG 与 ZIP 在稿件编辑器「检查与导出」另行下载。实际打开文件，检查遮挡、截断、引用和正文一致性。草稿也能导出预览，因此下载图片不等于正式批准；系统不会自动发布。

「效果复盘 → 试点验收」可记录该有效交付版本的人工结论；没有测量的工时留空。只有实际发布后才在「发布数据」登记真实链接与指标。合成演示不要登记为客户接受、真实收入或业务效果。

## 7. 保留失败样本，说明限制

| 练习 | 应观察什么 |
| --- | --- |
| 新任务要求资料里没有的 `售价` | 显式必需参数检查停止生成，不能靠相近型号资料放行 |
| 同型号、同参数填写不同值并申请核验 | 冲突被指出；系统不自动判断哪个值正确 |
| 修改已批准稿件 | 旧批准失效，重新审核后才能取得正式交付 |
| 撤销或过期资料 | 后续检索、批准或交付检查排除失效证据 |
| 查看脚本的自由问答报告 | 保留误接收等坏例；流程检查通过不代表所有答案正确 |

只在这个临时环境中做撤销或冲突实验。参数契约与自由问答应分别报告：前者验证明确字段是否具备，后者仍可能把主题相关误当作可回答。不要通过删除坏例提高展示分数。

记录本次日期、提交、命令、检索/生成模式、输出路径、实际成功与失败项。代码检查使用 `./scripts/check.sh`；进一步的源码阅读与修改路线见 [开发交接指南](../CONTRIBUTING.md) 和 [学习指南](learning-guide.md)。团队试点安装和环境边界见 [SETUP](../SETUP.md) 与 [SaaS 运维](saas-operations.md)。
