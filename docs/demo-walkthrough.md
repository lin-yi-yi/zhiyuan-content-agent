# 知源 v0.8：从资料到交付的演示流程

本流程对应当前五个主入口和三标签编辑器。用于首次体验、修改后的人工回归，以及学习时解释设计。实际测试结果记录在 [v0.8 验收](validation/v08-workbench-acceptance.md)，本文不预先承诺测试通过或在线模型生成成功。

演示优先使用合成资料。项目样本、本地生成和演示指标不能表述为真实客户效果。

## 1. 启动，认清两个独立选项

项目根目录首次运行：

```bash
./scripts/setup.sh
./scripts/start.sh
```

已经安装依赖时只需启动。打开 [本地工作台](http://127.0.0.1:8765)，顶栏应显示「本地 · 免登录」，侧栏有：

1. 工作台。
2. 资料与信源。
3. 问答与创作。
4. 审核与交付。
5. 学习中心。

设置入口位于顶栏和侧栏底部。默认数据保存在 `.data/demo.db`，正常停止在启动终端按 Ctrl+C。

**检索方式和生成方式是两个选项。** 默认检索是真实 FastEmbed 中文向量与本地 Qdrant；默认生成是规则或原文摘录，不需要聊天模型密钥。首次建立语义索引可能下载模型。没有模型缓存又无法下载时，可以明确采用备用词项模式：

```bash
RAG_RETRIEVAL_MODE=lexical ./scripts/start.sh
```

词项模式不代表语义向量已经验证。切回语义后，为资料重建对应索引；同模型的 semantic/hybrid 共用语义索引。

## 2. 导入一份能核对的资料

进入「资料与信源 → 我的资料」，选择当前知识库，也可以新建专门的练习知识库。

- 文件方式：选择 MD、TXT、文本 PDF 或 DOCX。
- 粘贴方式：填写标题和至少 40 字符的正文，点击「下一步：检查正文」。

等待提取预览，检查标题、正文与遗漏提示。修正后点击「确认入库」。**没有确认前，提取预览不会成为可检索资料。** 成功后使用「用资料提问」或「用资料创作」，目标页面会保留这份资料所属的知识库。

可以直接粘贴以下合成正文进行功能演示：

> 本练习产品只向用户提供 Markdown 文本和 PNG 卡片的下载，不支持自动向外部平台发布。内容草稿生成后必须由人核对原文与引用。审核通过表示本次内容已被确认，不表示已经发布。已通过的正文或卡片被修改后，应重新进行人工审核。没有足够资料支持的问题应明确说明证据不足，不应补写未知的产品功能。

导入时需要知道的限制：

| 输入 | 当前范围 |
| --- | --- |
| 单文件 | 不超过 1 MiB |
| PDF | 最多 50 页；读取文本层；扫描件无文本时提示 OCR 未支持 |
| DOCX | 正文与表格文字；图片、批注、页眉页脚不导入，复杂阅读顺序需核对 |
| 提取正文 | 40～120,000 字符；过长内容需要拆分 |
| 二进制解析 | 独立子进程；超时或资源限制会明确报错，可拆分或粘贴正文重试 |

检查一个扫描 PDF 的失败提示，或在含图片的 Word 中检查遗漏警告，能证明系统区分“支持文件格式”和“完整理解文件内容”。不要把这一步描述成 OCR 或多模态识别。

若使用项目内置资料，进入「学习中心 → 岗位与项目 → 载入演示资料」。默认库会得到人工编写的来源引用、人工审核、统计口径与失败恢复资料。`demo://...` 是合成来源标识，不是外部网站。重复载入会更新同源演示资料，不要用它保存自己的内容。

**验收观察：**资料列表有内容及片段数量；能查看原文；提问/创作继续使用选中的知识库；失败时有明确原因。

## 3. 提问，核对引用，再试一个无依据的问题

进入「问答与创作 → 知识问答」。确认知识库正确，「回答方式」选择「原文摘录 · 无需密钥」。

先问：

> 审核通过后会自动发布到外部平台吗？

点击「提问 →」，检查回答和下方「回答依据」。对照原文，确认没有把“审核通过”解释成“已经发文”。展开「检索设置与实验」，还可以点击「只查看检索结果」，区分候选片段与最终回答采用的证据。

再问：

> 火星探测器采用什么轨道转移方案？

当前练习资料没有相关证据，应拒答。若实际出现错误接纳或误拒，保存问题与片段作为失败案例，不要为了演示好看而忽略。

可这样解释：系统先找资料，再判断证据是否足够。相似度表示相关性，引用编号有效表示能定位到片段；两者都不自动证明回答的每一句话正确。

配置在线模型后，可以选择对应模型复测。问题和检索片段会发送给所选服务。只有实际得到结果并检查引用后，才记录这次在线生成是否通过；“已配置”不等于“已验证”。

## 4. 显式比较混合检索

在知识问答中展开「检索设置与实验」，选择：

- 语义检索：使用当前语义索引。
- 双路融合：BM25 词项候选＋向量候选＋应用层 RRF。
- 词项检索：不依赖向量的备用方式。

默认仍跟随系统配置。单次下拉选择只影响本次检索或问答，不会修改内容任务的全局配置。混合检索需要已有语义索引，模型或索引失效会报错，不会伪装成完整双路结果。

选择同一个知识库、同一个问题和相同证据数量，对比命中内容。RRF 根据名次融合不同量纲的结果，排序分不是正确概率，也不能拿来直接套用余弦阈值。

复现有记录的真实模型对照：

```bash
.venv/bin/python scripts/evaluate_hybrid_retrieval.py
```

脚本使用临时 SQLite/Qdrant，不读写运行中的用户知识库，不调用在线生成模型；首次可能下载 BGE 模型。报告默认写入 `.data/hybrid-retrieval-evaluation.json`。

2026-09-19 的 7 份合成文档、21 题对照中：混合模式实际引用召回比语义模式更高，但候选 Recall@3 与 MRR 更低；两者都错误接纳过近似主题，混合也出现把正确文档挤出 top-3 的坏例。展示这些取舍，不宣称整体更准。详见 [混合检索实验](research/v08-hybrid-retrieval.md)。

页面下方「质量检查 → 固定样本评测」是另一个实验：它使用默认知识库的内置 12 题与系统默认策略，不跟随上方选中的知识库或单次检索策略。先载入对应演示资料再运行，并下载完整报告。检查候选召回、实际引用精度与召回、可答问题误拒和无答案问题错误放行；引用校验率不是事实正确率。

## 5. 从明确目标生成内容

进入「问答与创作 → 内容创作」，或者从资料入库后的「用资料创作」继续。填写目标：

> 根据当前知识库，写一份说明引用、人工审核与发布边界的快速指南。

选择练习知识库，生成方式保持「本地摘录 · 无需密钥」。展开「更多要求」可以调整受众、特别要求和真实案例；没有真实经历就留空。默认启用知识库作为事实依据。

「结合指定网页资料」仅处理你填写的参考链接，不进行自主全网搜索；取消勾选后不使用这些链接。「额外评估选题价值」只控制选题评分，正文质量检查仍会执行。

点击「生成内容草稿 →」。主界面只显示准备资料、生成与检查、人工审核三个阶段，细节位于折叠区。观察：

1. 检索得到的依据是否与目标相关。
2. 正文和卡片是否生成，片段编号能否对应到本次资料。
3. 任务是否最终停在「等待你审核」。
4. 「质量建议」是否指出可改进之处；有条件修订不等于内容自动合格。
5. 「执行详情与审核历史」能否看到步骤状态、耗时与历史记录。

本地模式整理和摘录资料，不代表调用了大语言模型。在线模式的模型自评分也不是客户验收分数。生成期间不能修改该任务的稿件。

## 6. 用三个标签编辑，完成一次退回与重审

先在待审核任务填写审核备注并选择「退回修改」，例如：

> 请将“审核通过”与“已经发布”分开说明，保留原文引用。

当前审核意见应保留在任务中。点击「修改原稿」或「编辑这份稿件」，页面会定位到该任务的指定稿件编号，而不是同选题的最新版本。

编辑器分为：

| 标签 | 操作 |
| --- | --- |
| 正文 | 修改文字并保存；需要更多设置时再展开 |
| 卡片 | 查看成品、调整卡片内容和样式；检查文字密度、分页与正文一致性 |
| 检查与导出 | 查看质量建议与检查清单，下载 PNG 或 ZIP |

修改后先保存，点击「返回审核任务」，再点击「修改后重新送审」。核对本次正文、来源与卡片，然后「审核通过」。

审核绑定具体内容版本。通过后的正文或卡片被修改，旧批准失效；历史决定会保留。原始引用资料被更新、撤销或删除时，不能沿用失效证据批准，需要重新取得有效证据。

**验收观察：**任务、稿件与卡片编号对应；退回意见可见；保存后返回原任务；重审结果与当前内容一致。检查清单勾完和质量分数不会改变正式审批状态。

## 7. 下载成品，区分交付与发布

打开「检查与导出」，选择「导出全部 PNG」或「下载 ZIP 内容包」。实际打开下载的图片和压缩包，检查：

- 导出的内容是否为当前保存版本。
- 标题、正文与卡片是否一致。
- 文字是否被截断、拥挤或覆盖，引用是否可辨认。

草稿也可以导出预览，因此下载成功不能作为正式审批通过的证明。系统不会登录社交平台，也不会自动发布内容。

外部发布后，可以在「审核与交付 → 效果记录」手动登记，再查看「复盘报告」。缺失指标与真实零值分别处理；累计数据采用快照口径，不能把多次累计值重复相加；已锁定的事前预测不能在看到结果后改写。这里仍是人工记录，尚未接入平台自动采集。

## 8. 演示失败，而不掩盖它

| 情况 | 应看到的行为 |
| --- | --- |
| 资料不足 | 任务停止生成并说明证据不足；先补资料或改变目标 |
| 在线模型失败 | 明确失败，不能把本地备用结果包装成该在线模型成功 |
| 中断任务 | 重启后标记为失败；由用户显式重试，不自动继续产生模型费用 |
| 从失败处重试 | 使用原任务保存的输入；已完成步骤可复用；改目标要新建任务 |
| 停止任务 | 在节点边界停止；已发给在线模型的请求无法撤回 |
| 改动批准稿件 | 旧批准失效，重新人工审核 |
| 文档解析失败 | 不把失败预览当完整资料入库；说明格式、大小、OCR或资源限制 |

如果用于面试演示，至少保留一份坏例：给出触发条件、错误表现、定位过程和验证方法。不要删除失败样本后只展示成功率。

## 9. 从刚才的操作进入学习

点击页面内的学习链接，或进入「学习中心 → 技术与面试」。目前有 **7 个模块、29 道面试题、10 项练习、26 个固定源码片段**。

推荐现场展示一次：

1. 选择「可信知识问答」，打开「面试自测」。
2. 先自己解释“带引用就不会幻觉了吗”，再展开参考答案、追问与误区。
3. 点击源码，找到答案放行与拒答的位置。
4. 标记自己的掌握程度，刷新确认本机记录保留。
5. 进入「动手验证」，按解释、复现、故意改坏、排错、验收五步完成练习。

题目搜索覆盖全部模块。自测记录与自己的回答只保存在当前浏览器，按模式、用户和组织区分；不上传，不跨设备同步，不自动认证能力。源码只读白名单文件，不能输入路径读取任意本机文件。

学习时说明边界：LangGraph 当前使用 SQL 步骤记录，未使用原生 checkpointer；混合检索不是 Reranker；Web 信源主要走 REST，没有自建 MCP Server；PDF 导入不是 OCR。后续方向在课程中标为学习方向或待验证。

## 10. 可选团队试点与开发检查

本地体验不需要账号。要验证组织、角色和数据隔离，先按 `.env.saas.example` 准备独立 `.env.saas`，构建当前前端再启动：

```bash
(cd frontend && npm run build)
./scripts/start_saas.sh
```

入口为 [团队试点](http://127.0.0.1:8766)，数据在 `.data/saas`，与本地 `.data/demo.db` 独立。成员与模型连接在「设置」管理。只读、编辑、审核、所有者权限由后端执行；课程对有效成员可读，进度仍只在本机保存。

团队模式是单机试点。真实支付、邮件验证/找回、MFA、分布式任务、公网生产部署与客户验收尚未交付。AIHOT 商业使用需要单独授权；飞书/企微、自动发布、自动采集、Obsidian 同步和 OCR 不要演示成已接通。

修改代码后的统一检查：

```bash
./scripts/check.sh
```

检查脚本执行后端与前端行为测试、Python 编译和生产构建。最终结果、浏览器检查与在线模型验证统一查看 [v0.8 验收记录](validation/v08-workbench-acceptance.md)。历史验收保留各自时间与版本，不作为本轮全部能力的替代证明。
