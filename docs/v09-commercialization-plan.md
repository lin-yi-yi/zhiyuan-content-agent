# v0.9 商业化计划：从品牌资料到可审核的内容交付

日期：2026-09-19。依据：[中国内容市场与平台约束研究](research/v09-china-content-market.md)、[主流产品与开源工作流参照](research/v09-content-workflow-benchmarks.md)。本文区分当前代码、产品假设和验证计划；不记录未得到的自动检查、浏览器或客户试点成绩。

## 产品定位

**把客户确认过的资料，转成有依据、符合品牌表达、可审可改的图文交付。**

主试点客户：**2–10 人、为专业服务或工业 B2B 客户制作内容的小型工作室**。优先从软件实施、设备服务、工业零部件等资料可提供、事实可核对的场景中选一个。第一轮每家只做一个客户品牌、一套主要流程，避免立即扩展复杂代运营矩阵。

备选：**同类 B2B 企业内部 1–3 人内容团队**，要求本来就有重复交付任务和明确审核人。团队规模只是招募条件，不是市场统计。医疗诊疗、证券推荐等高责任专业内容暂不作为第一批试点。

两份调研共同支持“品牌上下文、重复流程、多人交接和结果反馈”正在被主流工具打包成产品。国内 135 已提供团队协作、素材和审核能力，有赞把内容接到商家经营链路；Jasper、Copy.ai、Buffer 等也提供品牌、流程和审批结构。因此“能写稿、能接多个模型”难以构成独立卖点。[135 企业协作](https://www.135editor.com/books/chapter/1/286)、[有赞内容助手](https://help.youzan.com/displaylist/detail_5_5-2-271789)、[Jasper 平台](https://www.jasper.ai/platform)、[Buffer 套餐](https://buffer.com/pricing)

选择工作室为主试点，是对当前资料检索、审核和图文交付能力的匹配判断，不是已经发现的付费市场。公开产品说明证明竞品在提供这些能力，不能证明目标客户会购买本项目。主试点与备选分开记录，不能把两类人混成一个“转化率”。

## 第一性原理与价值公式

交付过程中，客户要付出收集资料、判断事实、写作、排版、协调审批和纠错的成本。用户最终需要的是按约定通过验收的内容，AI 生成只是生产步骤。

`每月净价值 = 已核实节省的人工与返工成本 + 可归因的增量毛利 − 软件费 − 客户另付模型费 − 迁移和使用成本`

人工与返工成本不能重复计算；一次性品牌资料整理也要记录并摊销。早期先验证节省工时和减少返工，增量毛利暂记为“未验证”。曝光、点赞和线索受分发、账户、受众与销售跟进影响，不能都归因于系统。

建议产品核心指标为：**每周被客户验收的内容包数及其每包总成本**。辅助指标是完成率、实际操作时间、首轮批准率、返工原因、支持工时、事实错误和素材串用。任务生成成功、模型自评分和平台曝光分别是不同指标。

一个内容包的试点定义：一份正文、对应图文卡片、来源信息、人工审核记录和交付清单。模板只规定内容组织方式，不承诺形成多个渠道的专属适配稿。

## 当前源码已包含的能力

| 当前能力 | 可以准确说明什么 | 必须保留的边界 |
| --- | --- | --- |
| 商业前台 | 品牌与资料、内容任务、审核交付、效果复盘；学习/面试/岗位入口退出前台 | 历史文档和未挂载的历史模块仍保留，不影响现行产品定位 |
| 三个固定图文流程 | 专业知识图文、产品与服务答疑、真实案例整理 | 不是视频生产、完整营销策划或任意可视化流程编排 |
| 品牌档案和快照 | 保存受众、语气、禁用表达、行动引导、关联知识库；任务保留创建时版本，档案更新有并发校验 | 品牌要求不是事实来源；同组织没有品牌级成员权限 |
| 有依据的创作 | 固定流程要求知识库依据，生成保留引用，资料不足时阻断或提示 | 检索相似、存在引用和真实事实成立不是一回事；审核人仍需判断 |
| 禁用表达检查 | 审核批准与交付时对配置的文字逐行做字面检查，不区分大小写 | 不能识别全部变体、隐含承诺或法律风险，不叫“自动合规审查” |
| 审批和正式清单 | 正式下载时检查批准状态、正文/卡片 hash 与引用当前有效性，返回 Markdown 清单 | 下载不自动发布，也没有自动产生客户接受交付的回执 |
| 本地生成策略 | 品牌任务可限制为本地规则与原文摘录 | 不是完整离线大模型，也不是整个系统的网络或资料外发控制 |
| 团队模式 | 组织隔离、账号角色、人工审核和调用额度 | 尚非多节点生产服务；额度不等于实际人民币成本核算 |

审核交付清单与 PNG/ZIP 卡片素材分别下载。修改正文或卡片后需要重新审核；已审批记录不应被作为后来版本的授权。

**本轮没有实现**：渠道专属适配、交期和负责人、外部客户免账号审批、真实支付/结算/发票、生产合规验收。也未交付全平台自动发布、效果自动采集、完整视频制作、品牌级访问权限或生产扩容。功能测试与现场演示由单独验收记录说明。

## 特殊需求聚焦为可验收条件

| 约束人群/环境 | 优先满足的需求 | 验收或边界 |
| --- | --- | --- |
| 非专业编辑、一人兼运营 | 选品牌、选模板、写目标即可开始；高级配置默认收起 | 找不到下一步、需反复配置模型/检索，视为可用性失败 |
| 专业人员和运营异步协作 | 保留来源、品牌快照、改稿与审核记录 | 试点须有真实审批人；免账号外审目前没有实现 |
| 多客户工作室 | 不混用品牌资料和已批准版本 | 首轮一个客户一组织；未实现品牌权限前不宣传任意成员隔离 |
| 不出镜的专业创作者 | 用真实资料生成图文说明与答疑 | 不以不出镜推断个人能力、身份或收益；先验证图文可交付 |
| 弱网、轻量设备 | 轻量服务、明确失败、保留已保存结果 | 后续再按真实中断场景验收恢复能力，不把本机运行称为全面离线 |
| 资料外发受限 | 清楚显示生成方式和外发范围 | 云 API 不等于本地；仅有品牌任务限制时，不能承诺全系统资料不外发 |
| 键盘或大字体阅读需求 | 可见焦点、清楚错误、可放大和易审阅 | 作为常规可用性要求；特定无障碍适配需真实用户参与验证 |

## 两周试点：先验证业务，再扩展平台

没有客户渠道时，先通过公开行业社群、服务商名录、线下活动寻找受访者。研究与系统开发不包含自动联系客户或代发招募信息。

第一轮访谈 10 人：6 位目标工作室负责人/编辑，4 位 B2B 内部运营/审批人。不同机构才算独立客户；请对方展示最近一次真实任务、修改记录、耗时、工具账单和失败后果。完整问题见 [访谈清单](research/v09-china-content-market.md#7-十人访谈与两周试点)。

选择最多 3 家**同一细分类型**试点：

| 时间 | 行动与需要保留的证据 |
| --- | --- |
| 第 1–3 天 | 完成访谈，确定资料使用范围、实际审核人、6 个真实任务和当前流程基线 |
| 第 4–5 天 | 整理一个品牌资料包，用两次历史任务回放；记录配置、写作、排版、修改、等待时间 |
| 第 6–11 天 | 每家至少 6 个新任务，总计至少 18 个；记录失败与放弃，不能只统计成功稿件 |
| 第 12–14 天 | 对照质量和总工时验收，核对支持成本，询问下一周期实际付费与继续使用意愿 |

为了避免“先做后找成功指标”，事先设定以下实验门槛：

- 至少 2 家真实付费并明确愿意继续；仅口头夸奖或免费使用不算。
- 每家至少 4/6 个任务获验收，中位实际操作时间较可比基线降低至少 30%。
- 首次正式审核通过率至少 70%；与现有方式相比不增加事实错误。
- 每家每周开发者介入不超过 60 分钟；客户资料串用、未经允许外发、未审版本误交付为零。
- 为每次任务记录放弃/退回原因；等待审核与操作工时分开，时间与支持记录可先由表格完成，当前系统未自动追踪全部工时。

这是小样本决策规则，不是已达成成绩或行业标准。使用相近内容类型、篇幅和质量标准比较，纳入入库成本，不能只比模型出字速度。

停止或缩窄：10 位访谈者中少于 3 位能展示重复痛点；没有真实材料或付费承诺；任务主要卡在拍摄、投放、销售而非本流程；两轮修改后验收仍不足 50%；每家都需要不同的大规模定制。如果有跨客户资料串用或未授权外发，先暂停相关处理并修复，再重做验收。

## 价格只是实验，不能当成市场结论

以下均为**访谈与试点的待测报价**，不是已经上线的付费套餐：

| 价格假设 | 试验范围 | 要验证的事情 |
| --- | --- | --- |
| **299 元/两周** | 一个品牌、6 个图文内容包、一次最多 60 分钟的初始化帮助；事前约定交付和退出条件 | 是否有人愿意为具体的资料到交付流程付费 |
| **399 元/月** | 未来单品牌套餐锚点；拟设内容包、席位、存储和模型预算上限 | 是否持续复用，月价值是否明显高于价格 |
| **899 元/月** | 未来多品牌协作套餐锚点；具体品牌数与服务范围由验证决定 | 多品牌管理增量价值是否存在，隔离、权限和支持成本能否成立 |

当前不售卖尚未实现的品牌级权限、全自动发布或私有化 SLA。品牌数和成员数不是同一个维度。相邻产品公开价只是参照，不能当作本产品的客户愿付价。

`每个验收包直接成本 = 所有尝试的模型/检索/图片费用 ÷ 验收包数 + 存储/流量分摊 + 人工支持和审修成本`

模型用供应商账单计价，失败与重试也计入。API 请求配额不能替代成本核算。试点把软件、调用额度和人工服务分开记账，不承诺无限量。

示例预算而非实测：399 元月费，模型与基础设施 60 元、支持 1 小时按 80 元计算，剩 259 元覆盖税费、研发、销售与利润；支持增到 4 小时只剩 19 元。早期应优先压低每客户支持成本，防止把大量人工代运营包装成低价 SaaS。付费试点也需明确实际收款主体、交付范围与退款安排，系统当前没有真实支付结算。

## 三阶段路线与投资闸门

| 阶段 | 目标与开发重点 | 进入下一阶段的证据 |
| --- | --- | --- |
| **阶段一：把一个交付场景跑通** | 以当前三种图文模板、品牌快照、资料依据、字面禁用检查和审核清单为基础；只修复真实试点卡点，收集工时/退回/支持成本 | 两周试点满足上述完成与付费门槛；至少有稳定资料提供者和审批人 |
| **阶段二：让团队重复使用** | 依据共性痛点增加交期/负责人、版本差异、客户审阅、品牌权限和可靠队列；先做一个渠道的真实格式适配，再考虑第二个 | 连续两个付费周期有复用，支持成本可控；能明确哪项改进带来续费 |
| **阶段三：有选择地上线与扩展** | 按具体平台准入接连接器并验证回执；完成真实结算、运维恢复、监控、数据与标识要求；按负载再服务化数据库和向量存储 | 有目标客户、正式权限、真实生产负载和可承担的支持成本，完成独立生产验收 |

平台连接按“未接入/可导出/授权待验收/已验收”呈现。上传成功、提交发布、平台审核通过和最终可见分开记录。抖音 SDK/H5 投稿对应用和营销场景有准入约束，不能用通用创作工具权限承诺企业营销自动代发。[抖音官方使用规范](https://partner.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue)

生成式内容的导出和发布还涉及适用的显式/隐式标识要求。交付说明或 ZIP 附件不等于图片自身满足完整标准，产品上线前须按实际文件和服务形态核验。[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[GB 45438—2025](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F32EA2A561F1886CD8D606513512D547)

开源参照按架构和产品组织方式借鉴。本轮没有把 Postiz、Ghost、Dify 或 Langflow 源码集成进系统；引入前需检查具体许可证和依赖。尤其不能把 Dify 的附加多租户条件忽略，也不能将 AGPL 简化为“禁止商用”。许可证快照与边界见 [开源参照研究](research/v09-content-workflow-benchmarks.md#开源许可参考结构与复制代码是两件事)。

暂缓通用拖拽 Agent 画布、全网自动搬运、全平台群发、完整视频时间线、通用 CRM、自建模型和没有客户的私有化产品线。只有当具体交付阻碍、付费和续费证据指向这些投入时再评估。
