# AIHOT 接入与信源使用

核查日期：2026-09-19。本次用途是用户的本地个人学习、阅读与项目开发。AIHOT 是外部聚合信源；接通数据不能证明其中新闻已经核实，也不代表取得外部商业使用授权。

## 两条接入路径

### 在项目里阅读：信源台

本地启动后，在左侧打开「信源台」。页面通过项目的固定域名连接器读取 AIHOT 官方 REST API v1，可选择过去 24 小时／最近 7 天、精选／全部、分类与关键词，显示标题、AI 摘要、推荐理由和来源链接。

各时间含义不同：

- `publishedAt`：原始来源发布时间；没有就显示未知。
- `discoveredAt`：AIHOT 收录时间。
- 页面最近成功获取时间：本项目读取数据的时间，不表示新闻发布时间或人工核验时间。

查询使用官方默认 `by=timeline`，时间窗与 AIHOT 页面口径一致；不能将“24 小时内收录／呈现的条目”全部描述成“原文在 24 小时内发布”。页面保留原始发布时间供核对。

「复制核验笔记」保留当前条目的摘要、时间、原文与 AIHOT 链接，明确标记待核验；不会自动加入知识库、生成文章或对外发布。核对原文并确认可使用范围后，可通过既有「知识资料」入口整理自己的笔记。

AIHOT 的 `/agent` 页面响应含 `X-Frame-Options: SAMEORIGIN`，不能直接跨域 iframe 内嵌。本项目使用官方数据接口渲染自己的阅读界面，提供打开原站的入口，不代理网页或删除防内嵌响应头。

### 在 Agent 中查询：直接连接官方 MCP

官方已经提供远程 MCP：`https://aihot.news/api/mcp`，匿名只读，无需 API Key。不需要重新封装或启动一个转售／转发 AIHOT 数据的 MCP 服务。

可选项目级配置位于本地 `.codex/config.toml`（未随仓库发布），本机配置仅启用以下五个官方工具；克隆仓库不会自动启用此 MCP 连接：

| 工具 | 用途 |
| --- | --- |
| `aihot_get_latest` | 过去 24 小时／最近 7 天的精选或全部动态 |
| `aihot_search` | 2–200 字关键词查询 |
| `aihot_get_hot_topics` | 当前热点榜，最多 10 条 |
| `aihot_get_story` | 根据热点返回的真实事件 ID 查询时间线 |
| `aihot_get_daily` | 最新或指定日期的日报 |

可以问：“用 AIHOT 查最近 7 天有关 RAG 的资讯，列出 5 条，分别给出原文链接和哪些事实仍需核验。”不要把未公开的客户资料、项目正文或凭证放进查询词。

项目级配置需在受信任的项目中加载。重新启动相关 MCP 连接或开启加载该配置的新会话，再确认工具列表出现；当前对话中已列出的工具不一定动态更新。原空目录 `~/Documents/ai-content` 的本地配置使用符号链接指向实际仓库配置，便于当前项目入口使用，没有修改全局 MCP 配置。[OpenAI 官方 MCP 配置说明](https://developers.openai.com/zh-Hans/docs/extend/mcp)

本次已通过正常 `initialize → notifications/initialized → tools/list → tools/call` 验证官方 MCP。实际协商版本为 `2025-03-26`，服务器报告 `aihot 1.1.0`；一次 `aihot_get_latest` 小样本调用返回 3 条。该结果仅说明本次服务可用，不验证新闻真实性、其他工具或长期稳定性。[MCP 验收元数据](validation/aihot-mcp-check.json)

Web 实测、浏览器验收与 198 项检查结果见 [本次验收记录](validation/aihot-acceptance.md)。

## 缓存、失效与运行开关

- 列表连接器只访问固定 `https://aihot.news/api/v1/items`，不接受上游 URL，不跟随重定向；现有通用网页导入的安全校验保持独立。
- 页面按用户操作读取，不提供持续后台监控。查询结果在进程内短期缓存；遵循 `s-maxage`、`ETag / If-None-Match` 和 `Retry-After`，刷新按钮不强制绕过缓存。
- 获取失败要显示错误与旧数据状态，不能把缓存当成刚发生的新闻；不同查询不混用缓存。这里只显示最近资讯，没有构建全量镜像或历史新闻数据库。
- 直接启动服务时 `AIHOT_ENABLED` 默认关闭；只监听 `127.0.0.1` 的 `scripts/start.sh` 为本地个人使用默认开启。要关闭可执行 `AIHOT_ENABLED=false ./scripts/start.sh`。
- Web 连接器开关与 Codex MCP 配置独立。关闭 Web 连接器不会禁用官方 MCP；如要禁用后者，在项目 MCP 配置相应表内设 `enabled = false`。

## 信源问题应拆成发现、核验、保存、使用

| 环节 | 处理方法 | 当前状态 |
| --- | --- | --- |
| 发现 | AIHOT 提供聚合线索；后续可以按授权增加官方 RSS、厂商更新、论文与 GitHub 发布信息 | 已接入 AIHOT 读取；其他连接器未实现 |
| 核验 | 打开原始材料，检查发布主体、日期、版本、适用范围和具体原句；关键事实记录支持或冲突证据 | 页面提供原文入口、待核验标签和核验笔记；没有自动事实核验 |
| 保存 | 保存使用者确认的资料、核验时间、来源版本和权利范围；保留聚合链路 | AIHOT 浏览结果不自动入库；沿用手动知识资料入口 |
| 使用 | 生成时关联具体证据；证据不足就说明未知；已失效的资料需要重新核验 | 既有项目有引用和审核；跨信源核验与撤回传播仍是后续工作 |

来源可以区分“官方原始材料、独立媒体报道、社区线索、聚合摘要”，但来源类型不应直接变成一个自动可信结论：官方材料能支持厂商说过什么，独立效果仍需测试；两个网站转述同一篇报道也不算两个独立证据。AIHOT 推荐分描述其筛选排序，不能解释为真实性概率。

后续扩展信源表时建议保存 `provider + provider_item_id`、原文 URL、canonical、聚合页、发布时间、发现时间、获取时间、核验时间、版本哈希、核验状态、权利范围和撤回状态。去重先按稳定 ID 与规范 URL，事件聚类只辅助合并，保留各来源身份。完整同步必须采用官方 snapshot＋changes 合同，处理更正与撤选；当前浏览器式时间窗查询不能冒充完整同步。

文章、网页或 MCP 返回内容都作为外部数据处理，不能让其中的指令改变系统权限或触发工具操作。将来连接模型时，应只传完成任务所需的已筛选材料，并保留引用。

## 商业化边界

[AIHOT 使用规则](https://aihot.news/terms)允许个人非商业、公益非商业和限定的组织内部使用及合理私有缓存。面向外部的商业产品、客户交付、代理接口、批量再分发，以及向外部提供的 RAG／模型产品，需要其事先书面授权；显示来源、只展示摘要、暂时免费或测试期都不自动豁免。

因此本次接入用于本地个人场景。未来对外 SaaS、客户演示环境或商业交付前，应核实具体授权范围；没有相应授权时关闭实时连接器，用自编样例或自己有权使用的数据演示。没有在本次工作中发送授权申请、取得授权或发布公网服务。

官方没有按条目 ID 获取单篇正文的公开 API。保留原文链接，不猜测正文接口、不抓网页绕过来源授权门禁。第三方原文的权利也不因聚合或 API 可读而转移。
