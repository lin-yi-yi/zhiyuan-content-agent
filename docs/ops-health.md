# 本地磁盘余量预检与处置

数据库可读不等于下一次写入有空间。`/api/health` 检查存活，`/api/ready` 检查数据库连接；`scripts/ops_health.py` 单独读取操作者明确选择的目录所在文件系统的余量，用于启动、导入、生成或备份前的人工预检。

这是一次性只读检查，不是持续监控或自动保护。它不会创建目录、读取业务数据库、加载 `.env` 或调用模型、通知和网络 API，不会删除文件、停止服务、修改任务或退回额度。已有 HTTP 健康接口和启动行为保持原样。检查通过不能保证下一次写入、磁盘配额、权限或业务流程成功。

## 选择目录和阈值

在项目根目录用 Python 3.12+ 运行。每个 `--directory` 是固定角色与目录的组合：`database`、`vectors`、`backup`、`saas`，每个角色最多一次。数据库角色填写数据库文件的父目录，向量和团队角色填写实际数据目录，备份角色填写准备保存归档的已有目录。

默认本地布局的数据库预检示例：

```bash
.venv/bin/python scripts/ops_health.py \
  --directory database=.data \
  --min-free-bytes 1073741824 --min-free-percent 5
```

已有向量索引和私有归档目录时，可以同时检查它们：

```bash
.venv/bin/python scripts/ops_health.py \
  --directory database=/absolute/path/to/content-data \
  --directory vectors=/absolute/path/to/qdrant \
  --directory backup=/absolute/path/to/private-backups \
  --min-free-bytes 1073741824 --min-free-percent 5
```

团队模式可以使用 `--directory saas=/absolute/path/to/team-data`。这些路径需要按实际部署填写；脚本不从环境变量猜测，不自行展开 `~` 或 `$变量`，也不自动创建缺失目录。未使用向量索引时不要提供虚构向量目录。目录包含空格时，给整个参数加引号，例如 `--directory 'backup=/absolute/path/with spaces'`。

`--min-free-bytes` 是正整数字节数，`1073741824` 为 1 GiB；`--min-free-percent` 是 0 到 100 之间不含 0 的百分数，最多 6 位小数。至少显式提供一项；提供两项时，两项都要满足。低于任一阈值为低空间，等于阈值为通过。示例阈值只是演示，不是适合所有语料量和备份大小的容量建议。

同一文件系统上的多个角色分别检查，不把它们相加成多份可用容量。需要根据即将导入、模型缓存、索引和备份的实际增量留出余量；备份与源数据同盘时尤其不能把同一份剩余空间重复预算。检查是当时的读数，稍后其他写入者可能用掉空间。

## 读取结果和退出码

工具向标准输出写固定字段 JSON，包含检查时间、总体状态、每个角色的状态、容量数值、阈值和固定原因代码；不输出目录原文、组织名称、文件内容或异常原文。参数错误也不会回显传入的路径。

| 退出码 | 状态 | 如何理解 |
| --- | --- | --- |
| 0 | `ok` | 本次所有明确选择的目录达到指定余量阈值 |
| 1 | `low` | 至少一个目录低于阈值，其他检查没有未知结果 |
| 2 | `unknown` | 参数错误、路径缺失/不是目录、读取失败或无效容量；不能当成通过 |

未知结果优先于低空间作为总体退出码；仍逐项查看其他目录。退出码可供操作者自己的本地调度或检查程序使用，本项目不会因此创建系统定时任务、发送通知或承诺持续检测。输出文件的保存权限、轮转和保留由操作者管理。

逐项原因代码为 `OK`、`LOW_SPACE`、`PATH_NOT_FOUND`、`NOT_DIRECTORY`、`STAT_FAILED`、`DISK_USAGE_FAILED`、`INVALID_DISK_USAGE`。总体参数错误为 `INVALID_ARGUMENT`，检查含未知项为 `CHECKS_UNKNOWN`。容量无法取得时保持 `null`，不写成零；未设置的阈值也为 `null`。

## 出现告警后怎样处置

1. **低空间**：暂停发起新的大批量导入、生成或备份，先确认目标文件系统和占用来源。不要按这个结果自动删除业务库、索引或锁文件，也不要直接终止仍在写入的任务。
2. **路径或读数未知**：核对当前启动参数对应的真实目录、挂载和访问权限，修正命令后再查。不要为了让检查变绿而创建一个空目录替代原业务目录。
3. **释放或迁移空间后**：以原阈值重跑预检，再实际验证一次读取、写入及业务流程。数据库已经报错或任务受理未知时，结合 [请求诊断](diagnostics.md)和 [用量核对](usage-reconciliation.md)处理，不盲目重放生成或退款。
4. **需要迁移或恢复**：遵循 [本地备份恢复](local-backup.md)或 [团队运维](saas-operations.md)的停机、锁和新目录恢复要求，保留原始数据。预检通过不替代完整恢复演练。

## 用临时目录学习故障

不要通过填满真实磁盘来练习。建立一个只存合成文件的临时目录，以很低阈值检查正常路径；再将字节阈值提高到明显大于所在盘总容量，观察退出码 1；最后还原原阈值检查恢复。文件不存在和传入普通文件的场景应为未知，不自动跳到祖先目录读取另一个盘。

运行专项检查：

```bash
.venv/bin/python -m pytest tests/test_ops_health.py -q
```

脚本本身只依赖标准库，异常环境下也可用 `python3 -I -S scripts/ops_health.py ...` 运行，仍需提供全部目录和阈值。这里的 `...` 表示按前面示例替换参数，不能原样粘贴。测试使用临时目录，未导入应用；完整应用回归仍使用 `./scripts/check.sh`。

单元测试和实际 CLI 演练分别记录正常、低空间、恢复和未知路径，并检查合成文件树保持不变。测试只改变阈值或注入读取故障，没有真正消耗全部磁盘空间，不能把阈值演练称为真实 ENOSPC 写入恢复测试。

## 检查范围

- 使用标准库的文件系统余量读数，未验证 inode、用户或容器存储配额、只读挂载、写入权限、远程文件系统超时及硬件健康。若路径位于网络挂载，操作系统读取状态可能产生网络 I/O；不保证任意路径的零网络流量或固定完成时间。
- 相对路径基于调用时工作目录；目录别名或挂载变化可能改变读到的文件系统，不能据此保证挂载身份或后续可写性。
- 不进行写探针、不打开数据库、不枚举资料、不初始化租户；无法证明已有文件的完整性。
- 没有持续采样、历史趋势、外部通知或无人值守故障处置。后续诊断汇总还需标明日志覆盖未知，不能用“未观察到错误”证明系统健康。
