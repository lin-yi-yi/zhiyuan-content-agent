# v0.10 商业试点：一个品牌的产品与服务答疑

更新日期：2026-10-03。定位延续 [v0.9 商业化计划](v09-commercialization-plan.md)。本文是实验计划，不是已经发生的客户、付款、提效或生产验收记录。先访谈 2–3 位可接触的负责人，确认重复任务、材料权限、审核人与付款人，再决定是否进入下方两周试点。功能检查见 [P0 本地验收](validation/p0-industrial-faq-2026-10-03.md)。

## 1. 谁付费，为哪项工作付费

**主买方：深圳服务工业设备、工业零部件企业的 2–10 人内容工作室负责人。** 人数用于招募筛选，不是市场统计；该买方画像尚未得到真实付费验证。

工作室编辑是日常使用者；客户企业指定的技术或产品负责人审核事实与使用边界；工作室负责人决定采购和续费。不要把可访谈的企业联系人写成已获得客户。

首轮每家工作室只选 **一个客户品牌、一个 `product_faq` 产品与服务答疑流程**：

> 客户授权的产品手册、FAQ、服务说明 → 固定目标与资料范围 → 有出处的答疑正文和图文卡片 → 人工修改与内部审核 → 客户指定审核人确认 → 正式交付清单。

每包包含正文、对应卡片、来源、品牌版本和审核交付清单。发布由客户或工作室手工完成；本试点不承诺获客量、曝光、销量或自动发布。资料不足时补资料或停止该任务，不编造产品参数、价格、效果或案例。

纳入条件：能提供有权使用的真实资料，已有重复答疑内容任务，有固定审核人，并愿意记录当前流程耗时。没有真实材料或审核人的团队只能做演示，不能纳入客户提效结论。首轮不接医疗诊疗、证券推荐等高责任内容。

## 2. 用什么现有方法作为对照

对照客户现在实际使用的 **通用大模型＋文档／素材文件夹＋编辑工具＋人工审稿**，而非只对照纯手写。基线与试点应尽量匹配内容类型、篇幅、资料复杂度和验收标准；保留任务编号和原始记录。

本次复核的官方产品页表明，相邻工具已经覆盖不少基础能力：

| 替代工具 | 官方说明及对本项目的意义 |
| --- | --- |
| [135 团队协作](https://www.135editor.com/books/chapter/1/286) | 支持团队共享素材、模板、文章和授权公众号。共享与排版本身不足以证明本项目值得切换。 |
| [Jasper 平台](https://www.jasper.ai/platform) | 提供品牌、知识、Agent 与内容流程。品牌语气和接入模型本身不是充分差异。 |
| [飞书制造业实践](https://www.feishu.cn/content/article/7598495377062431695) | 展示业务 API、AI 分类、提醒和看板的组合方式。现成协作工具也是替代方案；案例方自报效果不能当作本项目 ROI。 |

本项目要验证的是：指定工业资料能否更容易追溯、资料不足能否及时发现、修改后是否重新审核，以及在相同质量下，交付完整内容包的人工与支持成本是否值得付费。上述三页于 2026-10-03 复核，属于产品方的一手说明，不是独立效果评测。

## 3. 本轮记录功能与证据边界

v0.10 的轻量记录按每个内容任务（run）保存一条人工记录，并使用乐观版本校验。两人同时编辑时，旧版本提交应被拒绝；重新读取、确认他人修改后再保存。它不是完整客户 CRM、结算系统或事件仓库。

| 字段 | 本轮口径 |
| --- | --- |
| `cohort` | 试点批次，用于区分样本。不要把合成演示与真实客户混成同一批。 |
| `outcome` | `pending`、`accepted`、`rejected`、`abandoned`。未完成、退回和放弃都应如实保留。 |
| `baseline_minutes` | 可比旧流程的人工操作分钟数；填写时必须大于 0。没有可信基线就留空，不填 0。 |
| `actual_work_minutes` | 本次客户／工作室人工操作分钟数，包含审稿与返工；填写时大于等于 0。不要用模型运行耗时替代。 |
| `support_minutes` | 开发者额外配置、排障、解释等支持分钟数；填写时大于等于 0。与上一项分别记账，避免重复计时。 |
| `baseline_reference` | 可核对基线的任务编号、记录位置或说明；一个链接本身不能证明基线可信。 |
| `acceptance_reference` | 客户验收记录的位置或编号。记录客户确认与付款时分别引用证据，不把内部批准当成客户验收。 |
| `note` | 退回、放弃、比较限制或补充情况。不要写入密钥、账号凭据或无关个人信息。 |

这些是人工申报数据。系统保存了记录，不代表系统已独立核实客户身份、工时或声明真实性。实际客户确认应保留在双方约定的邮件、协作工具或签收记录中，再填写引用；本轮不自动向外部发送消息。

`accepted` 必须通过现有审核和内容 hash 门禁，不能给未审核或已经改动的版本登记当前验收。已有接受记录对应的内容后来变化时，旧接受记录应显示为 `stale`，不再算当前有效接受。`stale` 是记录与当前内容不一致的派生状态，不是人为把新版本再次选为接受的替代方式。

内部 `approved` 只说明内部审稿完成。客户是否接收、是否支付、是否续费是三个独立事实，不能由内部状态推导。

### 报表如何解释

- 统计范围内全部任务进入计数分母，包括待处理、拒绝、放弃、旧接受失效和没有完整工时的任务；不能只展示成功样本。引用报表时同时标明范围和总任务数。
- 缺失数据不视为 0；报表应能让使用者辨认完整记录与未填记录。
- **只有当前有效 `accepted` 且三项工时均完整的记录**参加本轮的合计节省率计算。记此集合为 S：

  `合计节省率 = [ΣS baseline_minutes − ΣS (actual_work_minutes + support_minutes)] ÷ ΣS baseline_minutes`

  正值表示这组已接受且资料完整的任务，在所录人工口径下节省时间；负值表示增加时间。无符合条件记录时显示暂无可比数据，不能显示 0% 或 100%。
- 同时报告 S 的任务数及全部任务数。这是一个被接受结果筛选后的子集，不能据此宣称全部任务或整个试点都提效。失败与放弃的工作量仍须进入试点外部台账和完整成本核算。
- 此公式是**合计节省率**，不是逐任务节省率的平均数、中位数、首次客户通过率或投资回报率（ROI）。禁止将它改写为上述指标。

### 本轮没有自动解决的记录问题

每个 run 只有一条可更新的人工记录，乐观版本校验不等于完整历史事件。当前功能未自动记录完整的每轮客户退回和首次提交事件，不能据此计算首次客户通过率；也未自动摊销初始化成本、核算人民币费用、保存付款与退款事实或计算 ROI。

这些缺口在试点中先由独立台账补足。模型 token、HTTP 额度和节点耗时分别是技术观测，不能直接等同于供应商账单、人工工时或客户价值。

## 4. 两周执行清单

首轮最多三家同一细分类型工作室，每家一个品牌。一个团队不足以支持市场普遍结论；无论最后进入几家，都记录实际样本量。

| 时间 | 负责人和动作 | 需要保留的证据 |
| --- | --- | --- |
| 第 1–3 天 | 项目负责人先访谈 2–3 位可接触的负责人，查看最近一次真实答疑任务；最多选 3 家符合纳入条件的工作室。与买方确定范围、固定审核人及报价是否接受。 | 任务与返工实例、重复频率、现有工具和费用、真实资料使用范围、审核人、付款人及付费或拒绝原因。没有授权不导入客户资料。 |
| 第 4–5 天 | 每家准备一套单品牌资料，用 2 个历史任务回放；核对基线可比性、演示引用与修改后重审。 | 初始化人工、支持工时、旧流程基线、回放错误与修复。回放不算新任务客户成果。 |
| 第 6–11 天 | 每家完成 6 个真实新任务，仅用 `product_faq`；编辑记录人工，开发者记录支持，客户审核人确认接受或退回。 | 每个 run 的人工记录、每轮审核事件、失败与放弃原因、最终对应版本、实际模型账单。全部尝试保留在样本中。 |
| 第 12–14 天 | 逐包对账，与买方核对时间、质量、支持和成本；明确下一周期是否付费继续。 | 最终验收引用、全部任务台账、收款／退款记录、继续使用决定及理由。输出继续、缩窄或停止结论。 |

若历史资料和授权足够，可选择 10–20 个历史任务做对照；这只是试点设计建议，并非已有样本或完成结果。独立台账至少包含任务编号、每次提交与退回时间、审核决定、返工原因、人工分钟、支持分钟、初始化分摊、全部模型尝试费用、其他直接费用和支付记录引用。把实际操作时间与等待审核分开；前者下降不代表整体交期必然缩短。

客户的原始资料、验收记录与付款证据保存在约定的受控位置。本仓库只放匿名摘要或合成样例，不提交客户材料、真实付款凭证或密钥。

## 5. 报价、成本与继续条件

保留已有 **299 元／家／两周**作为一次待测试报价：一个品牌、6 个答疑内容包、一次不超过 60 分钟的初始化帮助。报价前明确实际收款主体、范围、额外支持、模型费用承担及退出安排。这是实验锚点，**不是已验证的市场价格、已经售出的套餐或付款记录**。不承诺无限量、自动发布或尚未提供的私有化 SLA。

支付证据独立于内容验收。说愿意买、免费使用、提交报价或系统中的接受状态均不算实付；下一周期继续意愿与真正再次付款也要分开记录。

完整直接成本需要从外部台账核算：

`总直接成本 = 全部尝试模型与工具费用 + 基础设施分摊 + 全部人工审修与支持成本 + 初始化成本分摊`

`每个验收包直接成本 = 总直接成本 ÷ 当前有效验收包数`

无有效验收包时，单包成本不可计算，已发生总成本仍需报告。失败、重试、放弃和退回的成本都不能丢弃；人工使用双方事先约定的成本口径，不能为了显得盈利把开发者时间当免费。

沿用 v0.9 的以下实验决策门槛，但由相应证据分别验证，不声称本轮报表已经覆盖它们：

- 至少 2 家实际付费且明确愿意继续；每家至少 4/6 个新任务获客户验收。
- 按外部完整台账，匹配任务的实际操作时间中位数比旧流程至少降低 30%，且不增加事实错误。该门槛不是本轮应用的合计节省率，不能用后者替代。
- 首次正式客户审核通过率至少 70%，由外部逐轮事件记录计算；不能由每 run 一条最终记录或内部审核状态推算。
- 每家每周开发者支持不超过 60 分钟；总直接成本与实际收费能支持继续交付。
- 客户资料串用、未经允许外发、未审版本误交付为零。

以上是预先约定的小样本实验门槛，不是行业标准或已经达成的业绩。结果不确定、样本不足、基线不匹配时，直接记录无法判断，不补造提效百分比。

## 6. 停损与下一步投资

出现以下情况就停止增加功能，先缩窄或放弃当前商业假设：

- 首轮访谈无法确认重复任务、授权材料、固定审核人或付款人时，保留为求职作品，不增加客户功能；只有新证据出现才重启商业试点。
- 主要困难在拍摄、投放或销售，当前资料到答疑流程没有解决关键工作。
- 两轮修改后客户验收仍不足 50%，或每家需要互不相同的大规模定制。
- 支持工时持续超过门槛，完整成本无法由可接受报价覆盖，或没有重复使用与实际付款。

发生资料串用、未授权外发或未审交付时，暂停对应流程，修复并重新验收后再继续。不要在发生此类问题时只用更多成功样本冲淡失败。

满足试点门槛后，再从客户已有工具中选 **一个 n8n／飞书通道**：例如将已批准且有效的交付清单写入指定飞书记录，或由 n8n 调用受限接口完成一次交接。先取得真实授权、限定字段和目标，再验证权限、重复执行、错误恢复、回执与实际可见性。HTTP 200 或配置完成不等于客户收到正确版本。

本轮未声称已接通该通道，不自动给客户发消息。只有相同交接问题反复阻碍真实交付时才实现；不同时接入多个系统，不扩展成通用企业 AI 平台，也不提前开发全平台分发、支付系统或大型 CRM。

求职展示可以准确说明当前代码怎样支持资料检索、证据边界、人工审核、API 和试点记录。商业经历只能在真正发生客户使用、验收、付款后再写入；合成演示和本地测试应明确标注。
