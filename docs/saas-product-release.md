# 知源 v0.7｜小团队试点交付说明

交付阶段：单机 SaaS 小团队试点。本文说明当前产品能力与试点边界；未交付公网客户站点，没有可宣称已部署的客户服务器或生产域名。

## 为谁解决什么问题

知源面向需要整理产品知识、跟踪行业资料并协作制作内容的小团队，例如产品运营、内容运营与行业研究团队。

团队交付的不只是答案，还需要说明：结论来自哪里、适用哪个版本、谁核验过、内容是否获准使用。知源把**资料发现 → 人工核验 → 知识入库 → 内容生成 → 审核与交付**连接起来，减少反复找出处、使用过期知识和传递审批状态的工作。

适合先验证三类具体需求：网络访问不稳定但可以手动交付资料；不同客户或项目组织的知识不能混用；内容在交付前必须有人核对依据。它不自动保证结论真实，也不代替团队的业务责任人。

## 当前可用功能

| 环节 | v0.7 可用能力 | 使用边界 |
| --- | --- | --- |
| 团队空间 | 注册登录、组织切换、邀请链接、成员角色与停用 | 邀请由所有者转交，系统不代发邮件；未提供邮件验证、密码找回或多因素认证 |
| 资料整理 | Markdown/TXT 文件、粘贴正文、索引、编辑与去重 | 用户主动选择资料；不会自动读取本机文件或整座 Obsidian 笔记库 |
| 核验笔记 | 结论、出处、支撑摘录、版本、权利声明、到期时间 | 保存、确认、入库分开；用户核验不等于第三方认证，权利声明不等于已完成授权审查 |
| 知识问答 | 中文语义检索、引用回查、证据不足提示；过期或撤销资料排除 | 普通导入资料不会自动成为已核验资料；不会自动监测所有外部原文变化 |
| 内容任务 | 基于资料生成草稿与卡片，保留步骤、失败状态、重试及取消入口 | 本地演示模式是确定性流程与资料摘录；在线生成质量需单独验证 |
| 人工审核 | 通过、退回、修改后重提；已批准内容修改后撤销旧批准 | 导出包本身不是审批凭证，以任务审核记录为准；当前不强制双人分离审核 |
| 内容交付 | 内容预览、卡片 PNG/ZIP 导出、手动效果记录 | 不自动发布到公众号、短视频或其他外部平台 |
| 组织隔离 | 按已验证成员身份选择独立业务数据库及向量目录 | 属于单机应用隔离，不是每客户独立主机，也不构成已完成的安全认证 |
| 用量与运维 | 套餐额度、请求账本、审计、停机备份恢复工具 | 尚非完整支付计费平台；容器模板与正式生产验收分开 |

## 中文与有限网络环境

- 页面及主要工作流面向中文使用；默认启动方案支持本地中文语义向量，模型首次准备需要网络或预先准备缓存。完成缓存后，本地向量检索无需逐次请求远程嵌入服务。
- 可适配 DeepSeek、通义千问、豆包、Kimi，由运营方配置凭证，组织所有者选择启用和默认模型。卡片“已配置”只说明配置存在，不代表账号余额、网络连接或回答质量已经验收。
- 手动导入 Markdown/TXT 和 Obsidian 导出的笔记不要求登录海外资料平台；团队仍须正常登录知源。Obsidian 当前只有文件导入，没有插件、文件监听或双向同步。
- 外部信源、模型访问失败时显示失败或重试信息，不伪造成功。可继续处理手动导入资料；词项检索可由运营方明确配置为备用模式，语义失败不会静默伪装成语义成功。
- 启用远程模型后，相关任务及检索到的资料可能发送给所选服务。使用本地向量不意味着整条生成链路不出网；组织应先确认允许发送哪些资料。

## 信源与连接开关

| 连接 | 当前支持 | 谁决定能否使用 |
| --- | --- | --- |
| Markdown / Obsidian 文件 | 用户主动导入的资料 | 组织开关及资料使用权由团队确认 |
| GitHub Releases | LangChain、Dify、RAGFlow 固定仓库的维护者发布元数据及原始链接 | 运营方启用后由组织所有者开启；不开放任意仓库 URL、命令或完整发布正文采集 |
| AIHOT | 已有只读资讯连接器，保留来源与链接 | SaaS 默认关闭；运营方先取得适用商业授权，再开启运营授权配置与信源开关，组织才能启用 |
| 国内模型 | 运营环境凭证支持的模型调用 | 运营方配置，组织所有者启用；租户看不到密钥，也不能上传任意模型服务地址 |
| 飞书 / 企业微信 | 规划卡片 | 未实现聊天读取、通讯录同步或自动发送，没有可宣称已接通的能力 |

AIHOT 官方 MCP 使用公用地址，只说明有一个接口入口；公用地址、匿名可调用、共享配置都不等于商业使用或再分发授权。知源不接受租户随意提供 MCP 服务器地址或执行命令。公开 GitHub 仓库及其软件许可证，同样不自动授予其他新闻或第三方内容的使用权。

外部材料用于发现线索；入库应使用自己的核验笔记或已获得适用许可的内容。可追溯来源帮助审核，不自动证明事实正确或完成法律合规。

## 账号与协作权限

| 角色 | 当前职责 |
| --- | --- |
| 组织所有者 | 管理成员、连接、套餐申请和审计，同时具有编辑、核验及内容审核权限 |
| 内容编辑 | 整理资料、编写核验笔记、生成和修改内容；不能代替审核人员通过审核 |
| 审核人员 | 查看资料与问答、核验笔记、确认入库及审核内容；不能改写原文或管理团队 |
| 只读成员 | 查看团队资料、来源与内容，并使用知识问答；不能修改资料或通过审核 |

所有者可以自审，因此需要双人审批的团队应另外约定实际分工，不能把角色菜单当作系统强制的职责分离。组织切换不授权访问其他组织，知识库编号也不能代替成员权限。

当前默认每个账号最多以所有者身份拥有 **3 个组织**，全实例最多 **100 个组织记录**；运营参数只能下调这些上限。成员可以受邀加入组织，“拥有组织”的限制不等于“加入组织”的限制。这些是资源准入护栏，不是并发吞吐量、可用性 SLA 或可服务客户数的承诺，最终以当前代码与配置为准。

## 套餐与计量

试用套餐：每 UTC 自然月 **100 次 AI 请求**、**200 份已索引文档**、**3 个活跃成员**。团队套餐由运营方通过受控管理工具明确配置额度，本版本不提供未经验证的市场价格。

AI 请求按 HTTP 受理尝试计次，先预留额度；HTTP 请求失败会退回。已受理的后台任务后来执行失败，不自动退回。用量不是成功生成篇数、token 数或实际模型费用；模型费用需由运营方另行核对供应商账单。异常退出留下的预留需要人工核查，不能仅按时间自动退款。

“申请升级”只登记需求，不收费、不产生订单，也不立即提升权益。成员与文档上限按实际使用检查；降低套餐不自动删除已有成员或资料。

## 一次可复现的演示

1. 按[运维说明](saas-operations.md)在本机启动 SaaS，所有者创建组织，邀请编辑和审核人员；试用套餐使用三个成员即可。
2. 在“连接中心”检查真实状态；先用本地演示模式和手动 Markdown 导入，避免把未配置模型或未授权信源作为前提。
3. 导入一份团队拥有使用权的产品资料，建立一条包含结论、原文出处、版本及到期时间的核验笔记。
4. 编辑保存笔记后，由审核人员确认，再单独入库；展示“保存”与“已核验入库”的区别。
5. 在“知识问答”提出一个资料能回答的问题和一个证据不足的问题，逐条打开引用核对。
6. 编辑创建内容任务，审核人员退回一次，修改后重提并通过，再查看交付内容及审核历史。
7. 撤销一条核验记录后再次提问，检查旧资料不再作为有效证据；切换另一组织，确认看不到原组织资料。
8. 查看“套餐与用量”和升级申请，说明受理次数与收费的区别；将编辑临时改为只读角色，验证写操作被阻止。

使用合成示例演示时应明确标注，不把虚构资料、离线规则输出或本地测试结果说成客户成效。

## 两周试点如何判断价值

建议先选一个三人团队、10–20 份已获许可的资料和至少 10 项真实内容任务。开始前记录人工流程耗时、返工原因及模型预算；以下为建议验收目标，**不是已实现的客户指标**。

| 验证项 | 记录方式与建议目标 |
| --- | --- |
| 依据能否查回 | 对交付稿的关键事实性结论逐条核对；每条均能定位出处、适用版本及核验状态 |
| 回答是否有支撑 | 用团队自建的至少 20 个问题人工判分；采用证据支持率目标 ≥90%，单独记录证据不足题的拒答情况 |
| 协作是否省时间 | 至少 10 项同类任务比较“找资料到审核完成”的总耗时，中位数目标降低 ≥25%；同时记录返工量，不能只比较生成速度 |
| 团队是否持续使用 | 第二周仍有编辑和审核人员共同完成任务，并愿意指定下一批真实任务；不能只统计登录或聊天次数 |
| 隔离与控制是否有效 | 跨组织访问、越权审核、超过配额继续受理均为零；到期/撤销样本能够按预期失效 |
| 成本与恢复是否可控 | 实际模型费用不超过试点前约定预算；完成一次停机备份、新目录恢复和两组织复核 |

出现跨组织资料暴露、越权审批或恢复数据损坏，应立即暂停试点并保留排查证据。来源授权不明确时停止该来源的使用；模型费用或网络失败超过预先约定范围时暂停对应连接。两周后仍无法减少返工或耗时、没有后续真实任务，应停止扩大功能和客户数量，先复盘资料质量、流程适配与需求本身。

## 商业正式上线前仍需完成

1. 明确首批客户、资料范围、处理目的、保存与退出方式、支持责任及实际数据路径；按具体服务性质核对适用要求，补齐授权与客户协议。当前没有“法律合规已完成”的结论。
2. 在客户确认的服务器和真实域名上部署 HTTPS，验收安全 Cookie、CSRF、权限、隔离、登录防护及外部连接；补齐邮件验证、密码找回和必要的账号恢复机制。
3. 在目标机器实测并发、长任务、索引内存、磁盘和恢复能力，建立监控、告警与异常预留处理流程。当前采用单主机、单进程，不能直接增加 worker 或多副本共享数据目录。
4. 如需收费，另行完成合同、支付、账单、退款和服务权益核对；如需双人强制审批或企业通讯平台集成，先确定实际验收要求再实施。
5. 以真实试点记录决定是否进入付费服务阶段。源码、自动测试、前端构建、Docker 模板及公网验收是不同证据，不能互相替代。
