# 功能闭环盘点与验收 · 2026-09-19

## 结论与当前入口

当前适合定位为「可演示、可继续打磨的本地 AI 知识与内容工作台」，尚不能作为已完成真实客户验收的成熟商用 SaaS。

日常入口为 http://127.0.0.1:8765 ，运行 `./scripts/start.sh` 即为免登录本地模式。本轮隐藏本地账号、团队和套餐入口，保留模型设置。账号、组织与权限代码保留在可选的 SaaS 模式（8766）；没有注释后端鉴权或给团队版增加绕过入口。两个模式的数据目录独立。

本轮已重新实际跑通：

**合成资料 → 真实中文语义索引 → DeepSeek 引用问答 → DeepSeek 内容工作流 → 人工退回 → 精确打开原稿 → 保存修改 → 返回原任务重提 → 审批 → 实际 ZIP/PNG 导出。**

还验证了：**发布前预测 → 本地模拟发布登记 → 手工累计指标 → 复盘**。发布登记不是向小红书或抖音发布；合成指标不是实际运营数据。因此技术链路与真实业务闭环必须分开描述。

## 本轮修复

| 问题 | 修复后的行为 |
| --- | --- |
| 从任务打开编辑页时可能落到最新的其他版本 | 携带任务、稿件、选题 ID；精确读取指定稿件；读取失败不回退到其他版本；可以返回原任务 |
| 勾完检查清单显示「已通过」，容易误认为批准 | 独立显示正式审核状态；清单显示完成/进行中/未完成；勾选不会批准任务 |
| 任务稿生成独立变体后脱离原审核链 | 后端在生成前拒绝该操作并提示回原任务修改重提；普通稿件保留变体功能并继承模型 |
| 发布后的预测还能修改、替换基准 | 已锁定/结算预测不可修改；只使用事前唯一关联基准；后补预测不进入校准 |
| 未录入指标被当作 0 参与排名 | 明确已采集/缺失数量；缺失不入排名、误差和表现建议；明确录入的 0 仍有效 |
| 页面累加每次累计快照，导致数据虚增 | 页面与报告统一只取最新时间、同时间最大 ID 的快照 |
| 预测浏览为 0 时仍显示 0% 误差 | 相对误差不可计算并排除均值分母；保留绝对误差及偏差方向 |
| 无效指标和发布时间偏移 | 拒绝负数、超范围比例及非有限数；新记录的带时区时间统一 UTC；发布时间默认空，避免页面加载时间误作发布时间 |
| 单条样本也推荐增减发布频次、未标注模板被当成优质模板 | 少于 3 条已测记录只描述观察与补数据；未标注维度不作策略判断；3 条仅为产品护栏，不代表统计显著性 |
| 项目总览仍使用旧版「没有账号体系」说明 | 按实际运行模式显示本地免登录或 SaaS 单机试点范围 |

| 发布与数据回流 | 本地发布登记、手工累计数据、预测校准与规则复盘 | 没有平台自动发布、定时发布、多账号运营或平台指标自动采集 |

| BOSS 直聘求职对照 | 保存岗位线索与能力映射 | 现有研究仅 10 条线索，1 条部分正文、9 条摘要、0 条完整 JD；不是持续更新岗位数据库，也不是完整招聘需求统计 |
| SaaS 基础 | 账号、组织隔离、角色、审计、额度及本机备份恢复已实现 | 按用户要求暂缓账号体验；未完成真实收款、邮件找回、分布式队列、公网部署、监控告警和客户试点 |

「模型已经适配但没有配置」和「功能没有开发」不同；「接口存在」和「真实服务已验收」也不同。旧 v0.6 本地环境有 DeepSeek 验收，上一轮 SaaS 验收使用本地规则，本轮再次验证的是本地模式的在线模型。

## 本轮实测证据

测试在独立 `.data/functional-audit` 数据目录、8767 临时服务进行，仅包含人工合成资料；没有读取旧知识库内容发给模型，没有向外部平台发布。

- 本地 8765 模型连接测试成功；8765 无需登录可访问业务接口，8766 匿名业务接口仍返回 401。
- 合成手册进入真实 `BAAI/bge-small-zh-v1.5` 索引；引用问答耗时约 1.07 秒，`answer_mode=llm`，引用 `chunk:1`，未拒答。
- 内容任务 #1 / 稿件 #1：约 16.15 秒到待人工审核。问答加工作流共 7 次 DeepSeek 调用成功，日志含真实 Token 与耗时。证据卡片采用规则摘录，一次轻量修订也是本地规则，不能说每一步均由模型完成。
- 浏览器完成退回、编辑、保存、返回原任务、重提、审批；修改后的正文可在原任务读取，旧评分失效，审核历史保留，最终 12/12 步完成。
- 浏览器实际下载 ZIP，192,599 字节，含两张 900×1200 PNG 及标题、正文、标签、评论引导文件；PNG 已检查可打开、文字未溢出。
- 模拟效果记录：2 条发布登记，1 条有指标、1 条缺失；先后录入 100/150 两份累计快照，报告取 150，没有相加成 250。预测 1000→实际 150，相对误差 85%；事后修改基准返回 409，负数指标返回 422。
- 最终统一检查：后端 484 项、前端请求隔离 4 项、稿件导航与累计快照 8 项全部通过；编译与生产构建通过。仅一项现有测试客户端弃用提示，没有失败。

### 内容质量未达到成品验收

本次内容任务自评分 **68/100**（流程门槛 75），提示第二页内容密集、封面收益点不足、缺少分页。浏览器审批备注明确为「仅通过合成功能验收」，不代表真实编辑或客户认可质量。

此外，卡片仍保留内部引用标识。面向公开发布，需要设计「可读来源脚注＋内部证据详情」的输出模式，不能简单去掉可追溯来源。

## 下一步顺序与验收标准

1. **先把生成结果做成可交付内容。** 针对一个具体场景完善卡片分页、正文与卡片一致性、证据展示、模板版式和人工重评；建立至少一套固定输入/期望结果/失败案例，逐条人工评审。当前 68 分应作为待改案例，不能用更多菜单掩盖质量问题。
2. **完成知识资料与信源接入。** 先增加 PDF/Word、导入状态与失败重试，再做 RSS、自定义订阅、信源切换与自动刷新。Obsidian 优先单向增量同步，稳定后再做双向冲突处理。
3. **选一个场景做真实试点。** 用允许处理的真实资料，记录完成时间、返工次数、引用正确性及人工改动。根据试点需要再接飞书/企微或发布平台，并补账号运营、计费和部署。

本轮最终浏览器构建为 `index-BnYrI5p_.js`，默认入口已重新打开并确认无需登录、隐藏团队与账号菜单。验收临时服务结束后关闭，独立合成数据和导出文件保留在 `.data/functional-audit`。

旧报告不会自动改写，请重新生成报告使用新口径。旧预测若曾被覆盖，原始值无法自动还原；旧 SQLite 时间若曾丢失时区偏移，也无法可靠逆推。当前复盘仍是人工录入数据上的规则观察，不是运营效果归因或自动训练优化。
