## 改动与范围

- 新增 `POST /api/v04/rag/question-scope`。默认规则不调用模型，在线模型需显式选择并通过已有组织连接检查；授权范围在调用前解析。输入和模型输出为封闭 schema，严格检查 Unicode 原文位置，候选与问题清单最多各 10 项。
- 不读取目录来猜问题，不补品牌或同义词，未知型号和资料中没有的参数仍保留。所有提案恒为待确认、完整性未证明；前端显示原文高亮，逐项加入清单后再次由人确认。
- query hash、组织、工作区、知识库、方式和供应商绑定本次提案；代次检查与取消保护晚到成功/错误，包括 A→B→A。清单已有内容和半填项目保留，满 10 项时提示处理。
- 模型 SDK 格式回退与 JSON 修复沿用现有适配器；结构错误 502、调用失败 503，不静默退回规则。非法输入含未配对 Unicode surrogate 时固定安全 422，不回显问题。
- SaaS 真实临时库验证权限、CSRF、禁用连接、额度和日志隔离；模型传输用 MockTransport。合法 SDK 响应在后续 schema 拒绝时仍保留上游成功记录，内部额度退回不意味着供应商退款。

操作、错误、计数与超时口径见[问题提案说明](../question-scope-proposals.md)，学习练习见[第七组实验](../learning-labs.md#第七组实验结构化问题提案与独立评测)。尚未做真实模型质量、账单或客户验收。

## 新页面实际点击

使用真实本机隔离 Uvicorn 服务、临时 SQLite 和词项检索，模型选择 local；通过 API 准备 1 份仓库合成核验资料和 1 个空知识库，页面操作用于验收本轮提案流程，准备步骤不冒充页面导入。

1. 默认规则方式和禁用的在线选项符合当前无凭证环境。输入“合成星桥 XP-24 的额定电压和售价是多少？”，得到两项；展开后型号和参数分别高亮原文位置。
2. 逐项加入清单，未确认时提问按钮禁用；确认后实际响应缺少售价并拒答，没有用电压引用掩盖缺项。
3. 删除售价后旧确认失效、旧回答清除；重新确认后返回已核验 `24 V DC`、chunk、版本与来源。该结果只证明缩小后的清单可答。
4. 修改为未知型号 XP-25，提案保持 XP-25；切换知识库后旧提案、已填清单和旧回答消失。
5. 带 emoji 的显式型号仍能提出正确候选；390×844 视口实测页面宽度 390，无横向溢出。最终构建重新加载后再次完成复合提问、加入、确认和缺项拒答。

本地截图保存在 `output/playwright/v017-scope-final.png` 和 `v017-scope-mobile.png`；仅合成资料。首开出现既有 favicon 404，最终加载的 console error/warning 均为 0，未观察到业务页面脚本异常。服务末次隔离检查为临时数据库、1 文档、外部模型记录 0、出站连接尝试 0；关闭仅本次浏览器和服务，应用生命周期正常结束。没有覆盖真实供应商或 SaaS 浏览器登录。
