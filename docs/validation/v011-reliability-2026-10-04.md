# v0.11.0 参数问答与本地可靠性验收

日期：2026-10-04。基线：v0.10.1 `32b2012`。本记录随对应功能提交，远程检查以该提交的 GitHub checks 为准。目标是补齐 [路线图](../../ROADMAP.md) R01–R04 的软件检查，同时提供可以亲自复现的学习材料；不宣称已经完成商业交付或学习者已经掌握。

## 变化与结果

| 范围 | 验收结果 |
| --- | --- |
| 必需参数 UI | 资料问答可填写型号与最多 10 项参数；允许询问未登记参数，缺项拒答；两个字段都空时显示未评估。切换库清空型号、参数及旧结果，请求代次防止旧回答回填 |
| 问答结构化模型声明 | RAG 问答指定参数时调用 JSON 适配，严格检查字段、型号、参数、值、引用、重复和遗漏；`mA` 与 `MA` 不视为相同。成功回答使用核验字段与原文，不渲染模型额外正文 |
| 资料变化 | 模型调用结束后刷新数据库，重新核对来源核验、版本、参数元数据、正文 hash 与引用片段；中途撤销、变值或改版本则拒绝旧结果 |
| 本地备份 | 显式选择数据库／向量路径，持有运行锁，使用 SQLite backup API 保存 WAL；文件白名单、清单、hash、私有权限；归档不覆盖，恢复只接受新或空目录 |
| 真实页面回归 | Chromium 从空白合成库通过页面完成核验、入库、品牌、FAQ 任务、批准、正式下载、编辑、重新审核和第二次下载；验证下载正文、出处、资料版本、hash 与当前批准稿一致 |
| 工程交接 | 新增路线、学习实验、本地恢复及浏览器回归说明；运行版本、前端包和项目声明统一为 0.11.0 |

## 复现

```bash
./scripts/check.sh
(cd frontend && npm audit --registry=https://registry.npmjs.org)
(cd frontend && npx playwright install chromium && npm run test:e2e)
.venv/bin/python scripts/evaluate_industrial_faq.py \
  --output .data/validation/v011/industrial-faq.json --serve --port 8772
```

浏览器打开输出的本机地址，进入「内容任务 → 资料问答」，选择「工业 FAQ 合成 main」：

1. 型号填写 `合成星桥 XP-24`，参数填写 `额定电压`，询问其电压，核对摘录 `24 V DC` 和 chunk。
2. 参数增加一行 `售价`，同时询问电压与售价，应整体拒答并只列缺失售价。
3. 改为 `上门服务响应时间`，应拒答；清空型号与参数后重问，应显示参数覆盖未评估。
4. 切换到空库，确认旧型号、参数和回答不再保留。

备份的完整命令及恢复校验见 [本地运维说明](../local-backup.md)；不要把实验路径替换成正在使用的资料库。浏览器用例和隔离机制见 [E2E 说明](../browser-regression.md)。

## 尚未验证

Agent 正文和卡片尚未接入这套声明校验，现有流程检查检索覆盖并要求人工审核。RAG 问答的结构化核对只验证显式字段与已核验摘录一致，不推断参数同义词、不检查原始资料真实性，也不判断使用者是否列全需求。自由问答原有坏例仍保留；通用事实正确性和完整问题覆盖不能从这批通过率推得。

备份验证使用临时合成 SQLite／Qdrant；整体一致性仍要求停止所有写入者，advisory lock 不能约束绕过锁的进程或硬链接别名。归档不自动加密或清除数据库内的秘密，SHA 不证明来源可信。

E2E 覆盖桌面 Chromium 的本地业务流程；问答页新 JSON 分支由后端 mock 测试验证，未调用真实模型。SaaS 登录、移动布局、全部 PNG／ZIP、当前 Docker 运行与业务恢复、供应商账单、客户验收和公网生产仍需分别验收。当前机器未安装 Docker，本轮不把容器模板当作运行证明。
