## 实现范围

1. 复用核验引用 JSON，增加可选品牌型号、参数和值。填了结构字段就要求完整三项、版本、定位以及值出现在摘录、摘录保留于正文。比较同知识库显式字段；不同值阻止核验，历史脏状态中的冲突也从检索/审核/交付排除。未核验新说法不自动推翻已核验旧资料；修改事实需新版本并重新核验。没有新增重型数据库或抽取模型。
2. 保存编辑/删除前的内容白名单快照、revision、hash、操作人及时间，供任务内部回查。不能恢复本轮以前没有留档的旧稿，也不是不可篡改审计存储。标题、封面、话题等可见文案统一检查引用。
3. 正式交付增加资料版本、文档/片段、hash、核验时间与有效期、原文定位；内部审核备注、旧内容历史和原始引用摘录不随交付导出。任务页面复用现有证据组件，可直接查看资料版本并打开核验笔记。
4. 增加可选 `required_facts` 参数契约，逐项检查品牌型号及参数名在本次有效检索片段中的核验依据；任何缺项停止生成。自由提问不推断全部要求，明确 `answerability=not_assessed`，保留原有坏例。
5. 新增固定工业 FAQ 合成集、隔离评测脚本及本人练习文档；清空模型 API 凭证、禁读 `.env`，使用临时数据库/索引、本地规则及词项检索。完整 HTTP/API 导入和生成，不用人工 seed 成功任务来冒充链路跑通。
6. README 与 API 对齐 v0.10 本地验证版，保留既有模板；试点范围收敛到单品牌工业 FAQ，未增加 CRM、自动发帖或新平台接入。

## 当前解释边界

结构字段比较不是语义事实核验，不处理型号别名、参数同义词、单位换算或任意自由文本冲突；须人工记录同一口径和适用条件。引用存在、字符串匹配及人工点击核验不证明资料真实。普通上传资料仍可参与通用工作流，但不能冒称已经核验。

资料管理和审核沿用当前 SQLite 单进程边界；本轮未新增数据库迁移。

本轮词项检索/本地摘录是低资源可复现验证，没有加载中文语义模型或调用四家在线模型。费用报告分开记录外部调用次数、未知/不适用 token、账单和未测人工成本；未用 0 替代未知价格。

本机演示、自动测试、真实平台联调、客户验收和付款分别记账。没有真实联调、客户使用、客户确认、付款、复购或公网生产验收。内部合成批准和试点人工记录均不能替代这些证据。

## P1 顺序与进入条件

后续更新：其中「运行观测与成本关联」已完成本地实现与模拟响应验证，见 [模型调用追溯说明](../model-call-tracing.md)。真实供应商对账仍未验证；下列其余进入条件继续适用。

1. **先选定一个入口及其负责人**：真实工具尚未确定时，只设计/测试清楚标为本地契约的请求进入、鉴权、范围、幂等、超时、失败回执、重试和批准版本回写。拿到具体平台权限后才做真实联调，不同时接飞书/n8n/Dify/Coze。
2. **运行观测与成本关联**：把 ModelRun 关联任务/步骤，明确模型、提示词版本、价格版本、耗时、失败与重试；缺失用量保持未知，估算与供应商账单分开。以一次可核对的调用链为验收，不以适配器数量凑功能。
3. **隔离部署与恢复演练**：复用现有 Compose 和备份脚本，实际做停止/恢复、备份/恢复、模型故障；保留读写和恢复结果。未在本轮扩大到公网或改生产数据。
4. **有试点后再补事件**：首次提交、退回、返工、审核、支持和客户确认，付款/复购另记；全任务成本含初始化、失败和支持。现有一条 pilot 记录无法推算首次通过率、完整历史或整体 ROI。

本人练习见 [运行、解释、复现、排错和修改](../industrial-faq-practice.md)。AI 生成代码及本轮工具验证不自动代表用户已熟练掌握；亲自完成的小修改与复现记录才是面试表达依据。
