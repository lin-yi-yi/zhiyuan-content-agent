# 多信源核验闭环验收

本页保留 v0.6 本地版历史验收。后续账号、组织及配额交付见 [v0.7 SaaS 验收](saas-pilot-acceptance.md)。

日期：2026-09-19。实际仓库：`/path/to/ai-content-agent`，分支 `codex/job-ready-agent-v06`。本地单用户服务：`http://127.0.0.1:8765`。本轮没有公开部署、发送授权申请或接入真实客户数据。

## 验收目标

完成两个来源的发现入口、本人核验笔记、结论引用关联、明确人工确认后入库、回答溯源，以及资料到期或撤销后停止使用。保留可复现的检索评测，而非仅提供设计文档。

## 实际走通的操作

- 浏览器读取 GitHub LangChain 项目 20 条发布元数据，显示版本、维护者、发布时间与本连接器读取时间。
- 点击创建本人核验笔记，标题、链接、渠道和版本带入；正文及引用结论为空，未自动复制摘要、未保存真实资讯。
- 浏览器填入项目自编合成示例，保存后为待核验且不能入库；勾选人工确认后才出现独立入库按钮。
- 示例笔记 `#5` 入库到默认知识库，问题“知源示例设备 A 的演练保修期是多少个月？”返回合成示例的 24 个月摘录、`demo-v1`、引用片段与核验笔记入口。
- 从回答返回核验记录，撤销后界面显示原索引失效；再次问相同问题，返回证据不足，知识库状态提示排除 1 份核验资料。
- AIHOT 与 GitHub 实际 HTTP 读取均为 `ready`，每种检查 2 条且均保持待核验标识。[元数据记录](source-evidence-api-check.json)不包含真实新闻或发布正文。
- 最终前端构建后，在知识库 `#2` 回答“极光项目每条结论需要保存什么？”，进入笔记 `#1` 并返回检索，知识库范围保持不变；侧栏默认笔记入口正确返回知识库 `#1`。

核验示例与评测资料均为项目自编合成内容，`example.com` 是标识地址，不是产品事实证据。

## 真实检索评测

通过 `scripts/evaluate_evidence.py` 在独立知识库 `#2` 中创建 3 份合成规范、运行 8 道题。实际检索模式为 FastEmbed `BAAI/bge-small-zh-v1.5` + 本地 Qdrant，回答为本地原文摘录，未调用生成模型。

| 指标 | 结果 |
| --- | --- |
| 可回答问题 | 6/6 接受 |
| 无关问题 | 2/2 拒答 |
| 候选文档 Recall@3 | 100% |
| 候选首位召回 | 100% |
| 候选片段精度 | 33.33% |
| 实际采用证据精度 | 100% |
| 实际采用证据召回 | 100% |
| 引用记录有效率 | 100% |

原始报告：[evidence-evaluation.json](evidence-evaluation.json)。候选精度与实际采用证据精度分开计算；候选有不相关片段，经过固定阈值后未进入这组回答。全部题目为开发样本，数量很少、非独立盲测，不能据此声称生产准确率。没有为这些题调整阈值。

同一脚本还实际检查：待核验不能入库、未明确确认不能核验、重复入库幂等、引用包含笔记与结论、撤销后排除且显示提示、过期笔记无法确认。这些检查均通过，报告保留结果。

## 审阅中发现并修复

1. 失效资料的高相似度向量可能挤掉有效候选：改为先按有效文档过滤再向量排序；使用 55 条失效高分片段与 1 条有效片段的真实临时 Qdrant 回归。
2. 删除知识文档后笔记仍显示索引完成：删除时同步笔记索引状态，通用入口不能绕过核验，从核验笔记显式重建可以恢复。
3. 回答期间撤销核验：返回模型结果后重新检查当前证据状态，已失效答案被丢弃。
4. 草稿审核旧引用：在原有片段存在、内容与范围检查之外，补充核验资料有效性检查，失效资料不能支持新一次批准。

## 边界

最终自动化检查：**293 项行为测试通过**（7.14 秒），Python 编译、TypeScript 与前端生产构建通过，差异格式检查通过。最终页面产物 `index-CJXrDt60.js` 已在浏览器重新加载验收。测试环境使用隔离 SQLite 和显式词项／合成向量；上面的 8 题报告另使用真实中文模型。现有 Starlette/TestClient 的 httpx 弃用提示 1 条不影响本次执行。

- 人工核验状态是用户声明，系统不自动访问引用网页、核对事实或判断蕴含关系。
- 时间失效规则依赖人工登记的到期时间，未实现远程文档变更监控。
- 普通上传资料仍能检索，但标为未登记核验与时效。
- 本轮完成本地闭环；身份认证、生产租户授权、计费、公网运维和商业信源授权仍属于后续 SaaS 阶段。
