# v0.16.0：私有诊断落盘与请求查询

日期：2026-10-04。开发基线为 v0.15.0 合并提交 `e91d14bb40e490232cbe057f8535f0681bbeef5d`。本轮让服务重启之后仍可查询保留的请求记录，增加磁盘容量限制和损坏时的明确未知状态。默认不落盘；需要操作者显式配置独立私有目录。它是 R08 的一个已验证切片，不是完整告警平台。

## 实现与约束

- 应用 lifespan 持有独立的日志锁；模块导入不创建文件。退出时先关闭业务存储，再关闭日志和释放数据锁；失败启动也释放已取得的资源。已有目录、当前 UID、私有权限、普通单链接文件及 inode 都参与检查。
- 仅接收既有诊断接口的白名单字段；落盘增加 `schema_version=1`，不捕获任意 Logger 文本。请求体、原始 URL、Cookie、参数、模型输入输出和异常原文不进入这些事件。第三方日志不在该保证范围内。
- 单文件默认 1 MiB，另留 5 份旧档；支持 8 KiB–16 MiB 和 1–20 份旧档。完整写入、文件及必要的目录 fsync 后才计入写入计数。I/O 故障或目录变化后停止续写并保锁，标准错误最多输出一次固定降级通知；通知自身也可能失败。
- 按 ID 查询 CLI 只读扫描保留窗口，不获取写锁，不导入应用或加载 `.env`。退出 0 为发现有效匹配，1 为窗口内未观察到，2 为参数错误或扫描不可靠；部分扫描即使命中也返回 2。`complete` 恒为 false。行损坏、权限错误、轮转竞态不通过输出原文解释。

操作命令、恢复步骤及限制见 [诊断说明](../diagnostics.md)。此实现是单机 POSIX 协作进程约束，不阻止同 UID 恶意修改，不提供防抵赖审计。同步文件检查与 fsync 有请求开销，未测生产容量；没有后台远程采集或通知。

| 阶段 | 实际检查 |
| --- | --- |

| 请求定位 | 带合成敏感标记的未匹配请求被拒绝，伪造 ID 被替换；按响应 ID 可查询，查询前后文件签名一致 |

| write 失败 | 只对日志文件描述符注入失败，后续健康仍 200；状态 degraded、丢弃 3 条、固定通知 1 次，后续文件签名不再变化 |
| fsync 失败 | 同上；不能把已写入可见字节解释为同步持久化成功 |
| 损坏查询 | 停服后追加带敏感标记的半行；查询返回 partial/退出 2，不泄露该标记 |
