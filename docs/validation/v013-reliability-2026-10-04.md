## Chrome 问答页面实测

使用 Playwright CLI 的独立 Chrome 会话和临时服务 `scripts/browser_regression_server.py --port 8789`。API 预先写入一份已核验的合成 XP-24 规格资料，建立一个有资料知识库与一个空库；随后在页面进行以下操作。材料准备不是通过页面完成，本节不冒称资料入库 UI 验收。

| 操作 | 观察结果 |
| --- | --- |
| 打开目录、选择额定电压、手填售价 | 自动填入所选参数，但没有自动勾选确认；未确认时参数提问按钮不可用 |
| 确认电压与售价后提问 | 明确拒答，缺项列为 XP-24 / 售价；不会用相关电压资料补造价格 |
| 改问题、删除售价、重新确认 | 修改取消旧确认；只核对电压可答，显示合成资料中的 24 V DC |
| 将原型号改为 XP-25，再选择目录 XP-24 | 未知 XP-25 原行保留，已知型号加入第二行；两个型号一起核对时缺项拒答 |
| 换为空知识库 | 旧参数与确认清空，目录显示 0 项 |
| 延迟有资料库的目录响应，再切换到空库 | 使用浏览器路由暂缓真实本机响应；释放旧响应后，旧条目没有覆盖新库，空目录保持正确 |
| 375 × 900 窄屏 | 参数行竖排，确认文字可读，没有横向溢出；已知电压仍可提问和显示依据 |

本轮修正了全局 input 宽度规则导致确认框文字挤成竖排的问题。最后一次页面检查没有控制台错误或警告；首次打开时曾出现已有的 favicon 404。独立页面会话及临时服务随后关闭。

## 目录与工具契约

目录仅返回当前知识库中仍有效的核验参数标签与出处，不返回参数值或全文，不调用生成、embedding 或远程抓取。测试覆盖资料撤销/过期/冲突、笔记与块完整性、规范化去重、分页、参数边界、工作区/知识库隔离，以及两个真实临时组织的相同数字 ID 隔离。目录当前遍历所选库，分页只限制响应大小，没有大库性能或稳定快照承诺。

工具 `rag.answer` 以前会忽略调用方提供的 `required_facts`；现在通过共享类型校验后传入同一回答服务。API 对照覆盖完整回答、缺项、错型号、复合要求、越界及跨库；缺项会在模型客户端取得前停止。工具参数中未知字段从忽略改为 HTTP 422，调用方需修正拼写或字段位置。没有把直接 API 所有顶层字段改成相同严格策略。

目录不解析问题，不自动确认，也不替换未知型号和参数。普通资料问答继续可用，空契约保留 `not_assessed`。详情：[人工确认范围](../question-clarification.md)、[工具参数说明](../rag-tool-facts.md)。

## 用量结算的失败路径

团队按受理尝试计数，不按生成成功、token 或货币计费。首次明确业务响应先冻结 accepted/rejected，再最多尝试一次结算。兜底 500、取消和无业务响应为 unknown，保留预留待核对。结算可能已提交但回执丢失，日志只写未确认，不能断言数据库仍是预留。审计或发送失败不逆转已受理事实；嵌套 finally 即使遇到清理故障仍恢复租户上下文。

新增 24 项覆盖提交前失败、提交后回执失败、真实 main 的正常 201/422、已提交业务副作用后异常、审计/send 异常、取消、诊断失败、两个组织并发及存储恢复。内层诊断不会吞掉下游 send 回调异常，SaaS/最外层仍负责脱敏。没有修改历史预留，仍需 [人工核对](../usage-reconciliation.md)。细节与复现：[结算故障说明](../usage-finalization-failures.md)。

没有完成真实网络断连、进程硬杀、磁盘容量、通知告警或生产账本恢复验收。尽力日志也不等于持久化审计保证。
