# v0.15.0：团队数据与向量索引恢复

日期：2026-10-04。基线为已整合的 v0.14.0 `84d80d0c9f6f884e01aea79883c7dc25d5a62c14`。本轮修复 SaaS 直接启动绕过服务锁的问题，增加双组织、真实 Qdrant Local 的停机快照和新目录恢复演练。输入均为合成资料，不使用业务库、真实账号或付费模型。

## 应用启动与关闭

此前 `.service.lock` 由 `start_saas.sh` 持有，直接使用 Uvicorn 或 Docker 默认入口没有取得同一锁。现在由 FastAPI lifespan 在初始化控制库之前持锁；启动失败或正常关闭时依次尝试关闭向量、租户和控制库，再释放锁。第二实例不能抢先初始化或关闭第一实例的存储。锁文件保留，避免删除锁文件产生两个锁持有者。

锁是同一数据目录中合作进程之间的单机约束，不是多机锁，也不能阻止任意外部程序直接改文件。停机备份仍需要操作者确认所有写入者停止。新增测试覆盖空组织库尚无向量索引时的活跃备份拒绝、同目录别名、跨进程启动、失败后释放及全部清理回调。

## 本机完整演练

环境为 macOS ARM64、Python 3.12.13。运行：

```bash
.venv/bin/python scripts/saas_recovery_smoke.py --runtime local \
  --output .data/validation/v015/local-recovery.json
```

本次工作树源码实际通过全部 9 个阶段，总计 14.751 秒；这不是生产恢复时间或 SLO。归档为 7 个文件、459,870 字节，其中 2 个组织的真实向量目录共 4 个文件。服务 UID 为 501，恢复前后本地模型记录各 2 条、外部模型记录和出站连接尝试均为 0。最终原库和恢复库均记录应用生命周期关闭完成，清理错误为 0。

| 阶段 | 必须实际成立的条件 |
| --- | --- |
| 活跃空库保护 | 组织尚未建立、Qdrant 尚未打开时，备份因应用服务锁而拒绝 |
| 双组织基线 | 两位 owner、一个受邀 viewer；组织间文档与 chunk 数字 ID 碰撞，但正文 hash 不同；semantic/hybrid 均只返回本组织内容 |
| 原库追加 | 停机备份后在原库新增一份资料，得到与备份不同的逻辑签名 |
| 损坏拒绝 | 修改归档向量成员一个字节且不更新清单；恢复因 hash 不符拒绝，不发布目标目录 |
| 文件恢复 | 新目录的每份恢复文件与清单 SHA-256 一致 |
| 已有目录保护 | 再次恢复到已有目录被拒绝，目录文件指纹没有改变 |
| 原库保护 | 恢复前后，已停机原库文件指纹一致 |
| 恢复后业务 | 不携带旧 Cookie，重新登录并核对文档、向量查询、viewer 角色、CSRF、跨组织拒绝和套餐用量 |
| 原库保留新资料 | 再启动原库，备份之后新增的资料仍可查询，逻辑签名仍为追加后的版本 |

报告只保存允许字段、内容 hash 和不透明组织 ID；私有合成账号密码只在进程内，Cookie/CSRF 响应不写报告。脚本操作自己新建的目录；不接受现有业务目录。恢复前后真实控制库和业务库参与验证，向量由独立夹具替换为明确命名的 3 维常量向量。

首轮因夹具 `warning` 日志级别没有正常关闭标记而失败，没有计作通过；改为 `info`、保持 HTTP access log 关闭后，完整重跑通过。停机门禁同时检查进程退出状态和生命周期完成标记；强杀、OOM 或缺少标记不能计为正常关闭。

## 证据边界与下一步

- 合成向量验证真实 Qdrant 存储恢复与租户过滤，不评测 BGE 模型下载、缓存恢复、语义相关性或检索准确率。没有重跑或修改冻结 FAQ 评测。
- SaaS 演练使用同一候选代码，未证明跨版本升级、降级或模型版本迁移。清单 hash 验证完整性，不是备份来源签名。
- 新登录有效不表示恢复的旧会话已被撤销；备份控制库仍含密码哈希及会话数据。演练报告不公开这些字段。
- 本机 Python socket 拦截不是操作系统防火墙；Docker 另外隔离运行网络。测试未覆盖公网 TLS、Compose、负载容量、真实断电或磁盘写满。
- 本轮未完成 SaaS 浏览器登录/组织切换验收、真实供应商账单、客户授权资料交付或商用生产验收。

后续继续补持续监测与告警、真实模型受控联调、目标环境容量和客户接受证据。操作与故障处置见 [团队恢复演练](../saas-recovery.md)，学习者需亲自完成 [第五组实验](../learning-labs.md)，再记录运行、解释、修改和排错能力。
