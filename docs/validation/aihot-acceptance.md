## 实际通过

- 官方 `/agent` 页面返回 `X-Frame-Options: SAMEORIGIN`；采用官方 REST v1 数据展示，没有尝试 iframe 代理或去掉限制头。

- 项目级 MCP 配置被本机 `codex mcp get aihot --json` 识别，实际仓库和原空目录入口都能读到同一个配置。未修改全局配置；当前聊天的动态工具发现尚未验收，需要客户端重新加载后确认。
- 真实本地 API 返回 17 条近 24 小时精选，保留原文链接和 attribution，全部标记 unverified；相同查询第二次从缓存返回；单字符关键词返回 422。见 [API 元数据](aihot-api-check.json)。数量是当次快照，不保证之后相同。
- Chrome 实际打开「信源台」，观察到来源、时间、待核验状态、详情和刷新等待提示；改为近 7 天并输入 RAG 后，结果区切换到对应查询，返回 24 条。未独立评估上游检索相关性。
- Chrome 点击「复制核验笔记」后显示成功提示，读取本次复制结果确认包含待核验标记、原文链接及 AIHOT 链接。外部新闻没有自动写入项目知识库。
- 已目视检查正常桌面视口的列表／详情排版；没有声称完成所有设备或无障碍测试。

## 自动化检查

最终 `./scripts/check.sh`：**198 项测试通过**，Python 编译检查、TypeScript 检查与前端生产构建通过。其中 78 项为新增信源专项测试，使用合成响应，覆盖：

- 未启用及状态接口不访问上游；参数错误在请求前拒绝。
- 不同查询的缓存隔离、有界缓存、最小间隔、ETag／304。
- 429／503 按 Retry-After 退避，网络错误只短期使用标明过期的缓存。
- 403 清除所有查询缓存并冷却；前端不能恢复后端已经清掉的旧内容。
- no-store 不留正文／ETag，no-cache 未重验证前不展示，二者均保留访问冷却。
- 固定上游地址、禁重定向、超时与响应大小限制、危险链接过滤。
- 异常数据结构受控报错；未知安全元数据、署名及权利字段保留。

测试仍有原有 Starlette/httpx 弃用提示，不影响本次结果。合成限流和故障测试没有通过真实高频请求触发上游限流。

## 保留的边界

- 这是阅读与核验入口，没有新闻自动入库、全量同步、网页全文抓取、自动事实核验或后台推送。
- Web 使用 REST；Codex 直接连接官方 MCP。项目未新建 MCP 服务，现有 LangGraph 内容工作流没有自动增加新闻工具调用。
- 只有短期进程内缓存；不提供全量历史数据、跨进程缓存或多用户服务保障。
- 原文链接可能指向媒体或社区转述，仍应继续追溯一手证据；AIHOT 推荐分不是正确率。
- 对外商业产品、代理接口和客户交付等须按 [AIHOT 使用规则](https://aihot.news/terms)取得相应书面授权；署名、只展示摘要或免费测试不自动构成授权。
