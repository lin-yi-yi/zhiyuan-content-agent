# 中断后预留额度的人工核对

团队用量记录的是 **HTTP 受理尝试次数**。它不是模型 token、人民币账单或资金退款：受理后的后台任务即使失败，也不自动退回这次受理额度。进程异常退出可能留下 `reserved`，不能仅根据经过多久判断它未被受理。

本地运营工具只处理已经查清的单条预留。没有自动过期、批量清账或公开 API；不知道请求最终状态时保持预留，继续查证。

## 先查证，再预览

使用明确的 SaaS 数据目录，先备份控制库并保存私有故障记录。不要对生产库做练习。只读列出预留：

```bash
.venv/bin/python scripts/saas_admin.py --data-dir /absolute/path/to/saas \
  reserved-usage --organization 替换为32位组织ID
```

`request_hash` 是完整 SHA-256，供精确选择；`request_ref` 是用于展示的前 12 位，不能用于执行处理。不会打印内部结算 token。

新请求的预留使用服务器生成的请求 ID 计算哈希，可与响应 `X-Request-ID`、脱敏请求日志和工作流尝试关联，见 [诊断说明](diagnostics.md)。历史版本使用独立随机标识的预留可能无法通过请求 ID 找回关联；不猜测、不补造历史来源。

根据 HTTP 接受记录、任务记录和故障证据，选择：

- `confirmed_accepted`：确认已受理，预留转为已使用。
- `confirmed_not_accepted`：确认未受理，退回预留的尝试额度。

保存核对记录编号、处理理由、操作者标识和一个新的 32 位 UUID hex 操作编号；可用 `.venv/bin/python -c 'import uuid; print(uuid.uuid4().hex)'` 生成操作编号。**重试同一次处理必须复用原编号及全部参数**，不要每次重试都生成新值。

默认命令只预览，不修改事件、计数或审计记录：

```bash
.venv/bin/python scripts/saas_admin.py --data-dir /absolute/path/to/saas \
  reconcile-usage --organization 替换为32位组织ID \
  --request-hash 替换为完整64位请求哈希 \
  --operation-id 替换为32位操作编号 \
  --decision confirmed_not_accepted \
  --operator ops-user-01 \
  --reason '根据故障记录核对，HTTP 请求未受理' \
  --evidence-ref INC-2026-001
```

检查输出中的组织、原状态、目标状态、周期、数量和处理后的计数。参数必须完整；该命令不读取 `.env.saas` 或从环境推断目标库。

## 执行与重试

1. 等待或处理仍在进行的请求，停止全部使用控制库的服务和其他写入脚本。
2. 用完全相同的命令追加 `--apply --offline-confirm`。工具持有与团队启动器相同的 `.service.lock`；活跃服务会阻止处理，不能删除锁来绕过。
3. 检查 `mode: applied`、事件状态和该组织审计记录，再启动服务核对用量。
4. 命令输出丢失时，重复相同操作编号及参数。已成功处理的同一操作返回 `mode: replayed`，不会再改计数或新增审计。换理由、操作者、目标或决定后重用原编号会被拒绝。

预览不是保留状态的锁定承诺；真正执行时重新读取当前事件，已由服务完成的预留不会被覆盖。历史月份只调整原月份计数。发现账本计数与事件合计不一致时拒绝处理，不能用此工具静默重算账本。

## 审计与限制

处理事件、用量计数和 `usage.reconciled` 审计在同一个 SQLite 事务提交；审计写入失败会回滚全部变更。记录原状态、结果、数量、周期、核对证据编号、理由、操作者声明及进程的有效操作系统 UID。原始请求 ID、正文、模型响应、密钥和内部结算 token 不写入这份新审计；操作者也不要把这些内容粘贴进理由或证据编号。

这是具备服务器文件访问权限的本地运营操作。操作者标识是声明值，操作系统 UID 用于追踪执行账号，**不等于 SaaS 会话认证或不可抵赖审计**；控制库可写入者仍能修改数据库文件。真实团队应另行管理服务器账号、访问日志、私有工单和备份。

停机声明及 advisory lock 不能约束绕过标准启动器的进程，也不能识别远程仍在处理的供应商请求。工具不会推断真实费用、追回 API 计费或补齐缺失模型用量。

## 学习与验证

在临时数据库里先调用 `reserve_usage`，然后依次观察预览、执行、原参数重试和冲突重试。解释为什么幂等键既要检查“同一编号”，也要检查“同一组输入”；再注入审计写入失败，确认账本没有只改一半。

自动测试见 `tests/test_usage_reconciliation.py`，覆盖真实 SQLite 并发、同事务回滚、跨组织拒绝、历史周期、计数不一致和 CLI 服务锁。自动测试使用合成故障证据，不代表真实运营人员已经完成一次业务核对。
