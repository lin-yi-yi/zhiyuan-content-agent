## 项目做什么

面向小型工业 B2B 内容团队，把一个品牌有权使用的产品资料整理成 FAQ／售前答疑内容包。主要流程是：资料与事实核验 → RAG 检索 → LangGraph 内容生成与检查 → 人工审核 → 可追溯 Markdown 交付。

项目包含品牌简报、知识库、内容任务、稿件与卡片编辑、组织隔离和人工试点记录。当前重点是完整交付一个有依据的内容包。

## 尚未完成

- **依赖持续维护**：2026-10-04 已记录的 npm 已知告警为 0；后续仍需跟进维护版本和新增公告，保持开发服务只监听本机。
- **真实模型与费用核对**：本轮追踪逻辑未调用付费模型，也未接入供应商账单；输入/输出 token 的统一单价估算不覆盖所有计价方式。
- **真实客户材料与验收**：固定评测材料是自编合成数据，标签待人工复核；没有客户付费、复购或 ROI 证据。
- **外部业务入口与运维**：尚未确定具体平台及负责人，未做真实平台回写、公网部署或生产恢复验收。
- **持续运维检测**：R08 仍部分完成。私有日志和只读查询已实现，保留窗口与扫描不确定性不能视作完整审计；磁盘 CLI 仍是一次性人工预检，持续指标、自动通知、OpenTelemetry 和真实磁盘写满/断电后的恢复均未验收。
- **目标环境门禁**：真实 BGE 缓存、跨版本 SaaS、目标机器、Compose/TLS、公网及生产恢复，未因合成 Docker 演练而完成；后续提交仍需检查其自身 CI。

已有实现与待完成事项分开记录，不把内部审核通过当作客户通过，也不把测试通过当作生产上线。

## 下一步顺序

1. 下一开发切片补问题原文到型号/参数清单的提案与人工确认，保留未知型号、缺失参数和歧义，并用独立解析评测及真实页面验证；尚未实现，不改写原冻结坏例。操作者可同时按 [诊断指南](diagnostics.md)独立练习编号查询和降级处置。持续告警与目标环境验收按 [开发路线](../ROADMAP.md)推进。
2. 明确费用上限和资料外发范围后，验证一次真实供应商调用及用量对账。
3. 选定一位资料负责人、一个品牌及授权资料，核对真实历史任务、业务入口、完整成本与验收口径。
4. 完成目标环境的部署、告警、备份恢复和升级回退，再决定是否进入真实小团队试点。

当前可立即复现的入口是 [安装与运行](../SETUP.md) 和 [工业 FAQ 练习](industrial-faq-practice.md)。
