# 从问题提出参数清单，再由人确认

v0.17.0 增加「内容任务 → 资料问答 → 从问题整理参数」。它把问题原文中的型号和参数提出为候选，帮助人核对范围；原有[参数目录](question-clarification.md)仍用于查看资料里登记的正式名称。提案不读取目录，不能因为资料没有价格而删去问题中的价格要求，也不能把未知型号换成库中相似型号。

当前有两种方式：默认有限本地规则，无模型调用；主动选择非本地回答模型，再选择模型整理方式，才向该供应商发送原问题。模型路径已完成协议模拟和错误处理验证，尚未进行真实供应商质量或账单验收。

## 页面操作

1. 输入完整问题，点击「从问题整理参数」。检查候选的型号、参数原文及位置，以及需要澄清的部分。提案只针对当时的问题和知识库。
2. 逐项点击「加入提案」。这一步只加入清单，不批准、不发起问答，也不覆盖已填项目。清单最多 10 项，已满时提示处理，不截断其他要求。
3. 对照原问题编辑和补全。提案保持原文名称，例如 `XP-24 / 电压` 不会自动变成 `合成星桥 XP-24 / 额定电压`；需要按资料登记和实际提问意图核实名称，保留资料中可能没有的要求。
4. 勾选「我已对照原问题，确认本次需要核对的型号和参数」，再点击「按确认参数提问」。已核验资料缺少任一项时拒答，并列出缺项。

修改问题、切换知识库/组织或整理方式，会丢弃旧提案与晚到响应；加入或修改清单后要重新确认。清空清单仍允许一般资料问答，其完整性保持 `not_assessed`。直接调用接口的程序需要自己实现确认流程；服务器验证 `required_facts` 的证据门禁，但不宣称证明某个人已经理解了完整问题。

例如：`合成星桥 XP-24 的额定电压和售价是多少？` 会提出电压和售价两项。假如资料只有电压，两个要求都确认后应缺售价而拒答。删除售价后返回电压只能说明缩小后的清单可答，不能说明原来的复合问题已解决。

## 两条解析路径

**规则方式**是可解释的有限语法：

- `型号：合成星桥 XP-24；参数：额定电压、售价`。
- `合成星桥 XP-24 的额定电压和售价是多少？`，自然问句中的型号需含 ASCII 字母数字编号。
- 以分号、句号或换行分开的、各自明确绑定的多条问句。

它不做同义词归一、品牌补齐、问句完整性证明或通用语言理解。否定、排除、指代、多型号归属不明和二选一等已识别表达会要求澄清；未覆盖的表达仍可能产生不合意候选，因此必须人工检查。含“或”的真实参数名（如“或门电压”）也保守要求澄清。超出有限语法的明确问题也可能要求手填，不强行猜测。

**模型方式**的初始提案请求只接收原问题和封闭输出 schema，不接收知识库资料、目录标签或评测标准答案。模型需返回原文片段和对应位置，后端用 Pydantic 校验字段、数量、类型与 Unicode codepoint 位置，再核对片段确实等于原文；额外字段、越界、重复项目或伪造片段均使整次提案失败。这个校验可发现结构或定位错误，无法证明模型没有漏读、错误绑定或误解语义。

模型使用现有 OpenAI 兼容适配器的 `chat_json`，不是供应商原生严格 schema 的保证。沿用有限格式回退和 JSON 修复，一次操作最多 5 次应用层 completion 请求（3 次主请求和最多 2 次修复），SDK 自动重试为 0。修复请求还会发送同供应商上次输出的最多 6000 字符及解析错误类型，仍不加入资料或目录。底层连接、读写和连接池操作的超时配置为 120 秒，这不是整次整理的总时限；未新增语义修复重试。页面取消只取消等待，不保证供应商停止执行或停止计费。

## 接口契约

```http
POST /api/v04/rag/question-scope
Content-Type: application/json

{
  "query": "合成星桥 XP-24 的额定电压和售价是多少？",
  "workspace_id": 1,
  "knowledge_base_id": 1,
  "method": "rules"
}
```

`query` 必须是 1–1000 个字符的非空原字符串，不能先裁剪再使用返回位置；额外字段拒绝。工作区和知识库可省略，按现有默认范围解析。模型方式需显式传 `method:model` 和 `provider`（`deepseek/qwen/doubao/kimi`），可选 `model` 最长 100 字符；规则方式不接受 provider 或非空 model。

响应包括 `schema_version:1`、原字符串 UTF-8 的 `query_hash`、方法及解析器版本、已解析的工作区/知识库、候选和问题清单。`offset_unit:unicode_codepoint` 表示 0 起始、左闭右开的 `[start,end)`，不是 JavaScript UTF-16 下标。浏览器以 `Array.from(query)` 核对，emoji、全角和组合字符不先规范化。`proposed` 仅表示当前提案没有 issues；所有成功响应仍固定 `requires_confirmation:true`、`requirements_complete:false`。

`issues.code` 只允许缺型号、缺参数、归属不明、否定、未支持问题及过多要求这六类；界面映射固定中文说明，不直接展示模型自由解释。没有可用候选也返回待澄清，不自动缩小问题。

| 情况 | 结果 |
| --- | --- |
| 输入、范围或配置无效 | 422，固定安全提示 |
| 模型结构或原文位置无效 | 502，`code:invalid_scope_proposal` |
| 模型调用失败 | 503，`code:scope_provider_failed` |
| SaaS 未登录、CSRF 不通过、伪造组织 | 认证/权限层拒绝，提案服务和模型不执行 |

权限与知识库范围在模型调用之前检查；SaaS viewer 可使用问答类提案，在线模型仍需组织已启用连接。模型调用使用 `step_key:question_scope`，通过 `invocation_id` 和 `request_index` 关联本次 `chat_json` 内部请求，不虚构 Agent Run；当前这些 ModelRun 字段没有直接关联 HTTP `X-Request-ID`。日志 success 表示 SDK 返回可读取响应，即使后续 JSON 解析失败也可能为 true，更不代表业务 schema、跨度或语义检查通过。调用日志尽力保存，记录失败不使业务失败。

本地规则不产生 ModelRun，也不消耗 AI 请求额度。模型提案沿用一次操作的受理额度：明确成功计一次，明确拒绝退回内部预留；这不是供应商 token 账单或退款。模型已经执行但提案校验失败时，上游仍可能收费。

## 可复现评测和学习

```bash
.venv/bin/python scripts/evaluate_question_scope.py \
  --output .data/validation/question-scope/report.json

# 如果需要把任何已记录质量坏例都作为命令失败：
.venv/bin/python scripts/evaluate_question_scope.py --fail-on-bad-cases
```

新题集有独立 `inputs.json`、`annotations.json` 和固定哈希清单。先对全部纯问题运行生产规则，再读取标签评分；推理阶段禁止通常的评测文件、`.env`、现有数据目录读取和网络调用。这是防止误用标签的回归保护，不是恶意代码沙箱。生成模型仅有独立协议 mock 测试，不能把 mock 输出当作模型质量。

报告分别列出契约/跨度、明确题的精确参数对、遗漏和额外候选、误澄清、需澄清题的错误提案、逐题坏例和时延。默认退出 0 表示评测完成；`quality_passed` 和坏例才表示本题集的质量结果，CI 绿色不意味着没有质量局限。本地规则模型费用不适用，计算成本未测量，不能把项目运行成本记成零。

所有新题均为开发助手自编合成数据，标签待人工复核，且本轮已用于修正规则；不是盲测、未见样本、客户资料或事实问答准确率。首跑及修复后报告分别保留。原冻结 FAQ 问题与坏例不修改，人工确认也没有被注入自由问答评测。实际数字和提交见 [v0.17.0 验收](validation/v017-question-scope-2026-10-04.md)，亲手练习见[第七组学习实验](learning-labs.md#第七组实验结构化问题提案与独立评测)。
