# v0.9 内容工作流产品与开源参照

调研日期：2026-09-19。范围：Jasper、Copy.ai、Buffer、Canva，以及 Postiz、Ghost、Dify、Langflow。基于产品官方页面和 GitHub 当日默认分支的 README、LICENSE；不使用 Star 数推断客户付费或商业成功。网站产品说明属于厂商对自身产品的陈述，不是独立的效果验证。本项目现状参照 v0.8 README 与验收记录，下面的产品方案是建议，不能视为已经开发完成。

## 第一性原理：用户愿意为什么付费

内容团队要完成的工作，是把真实的业务资料转化成受众愿意阅读、负责人愿意批准、运营能准时交付的内容。生成一篇文字只是其中一个环节。

本项目可验证的价值假设是：**让有专业资料、缺专职内容人员的小团队，按固定流程稳定交付一组可审核、可复用的中文内容。** 初期优先试点工业产品、软件服务、专业咨询等资料较完整且需要事实准确的业务团队。优先做售前 FAQ、产品讲解、客户案例改写、活动宣传；这个选择来自当前能力与场景的匹配，尚未得到访谈和付费验证。

可以用下面的账来验证，而不是只统计生成篇数：

`客户月度净收益 = 实际节省的人工作时 × 客户认可的工时成本 + 可归因的增量毛利 − 订阅/服务费 − 模型费 − 使用与返工成本`

起步时以节省工时、一次审核通过率、准时交付率为主要指标；线索与收入只有拿到真实发布、转化和对照数据才能归因。粉丝上涨、爆款概率不能作为当前产品承诺。

## 五条产品原则

1. **一个内容任务对应一份交付约定。** 先确定品牌、受众、事实资料、内容目的、目标渠道与交期，再执行。结束时得到稿件、配图/卡片、审核记录、发布说明与回执位置，不让用户在若干聊天记录中拼结果。
2. **品牌事实与表达风格分开管理。** 产品参数、价格、资质、案例要有依据和有效期；样稿负责语气，不能被模型当作新事实。品牌档案修改后，新任务使用新版本，旧任务保留快照。
3. **自动化负责重复动作，人员负责影响业务的判断。** 文稿生成、渠道拆分、排版、常规检查可以自动；依据缺失、价格承诺、客户案例、公开发布由指定角色确认。审批绑定具体产物版本，修改自动失效。
4. **先让交付包稳定可用，再扩展发布接口。** 同一批准事实可以适配不同渠道的标题、正文、标签、封面和视频口播稿。适配应带渠道预览与差异检查；资料节选也应保留内部可追溯依据。没有连接器时，提供人工交付和回填，不制造自动发布假象。
5. **优化客户成本，而不是堆生成量。** 每任务记录首稿时间、人工编辑耗时、退回原因、最终版本、实际模型消耗和发布结果。重复任务积累为受控模板，先用审核通过率与交付时间验证价值，再讨论传播和获客提升。

## 把“特殊”落到可交付约束

| 人群或环境 | 实际工作困难假设 | 值得做的产品约束 | 试点需验证的事实 |
| --- | --- | --- | --- |
| 工业/软件等专业型小团队 | 有参数、说明书和售前问答，缺持续内容人员；专业表述不允许乱编 | 从批准资料生成 FAQ、产品说明与图文；事实逐条可追溯；禁用无依据销量、案例和参数 | 每周任务数量、查证/改稿耗时、预算决策人 |
| 代运营或跨部门团队 | 客户资料与品牌容易混用，意见散落，最终版本难确认 | 品牌隔离、brief 模板、审阅意见、版本冻结、交付包与交期 | 每客户往返次数、延期原因、愿不愿为交付协作付费 |
| 网络或数据外发受限团队 | 资料不适合任意发给公网模型，外部服务可能不可用 | 明示本次外发内容和目标；批准资料白名单、受控国内模型或经过验收的私有接口；离线可编辑与导出 | 客户允许的部署位置、模型端点、资料类型与保留周期 |
| 时间有限、不出镜的专业内容创作者 | 具备经验，但难以拆稿和持续排版 | 固定栏目模板、图文卡片、口播稿和拍摄清单；用客户已有真实资料 | 是否反复使用同一流程、单次返工量、发布材料能否直接使用 |

以上不是四条同时展开的产品线。建议先选择第一行，兼顾第二行的审核交付能力。不要把“不出镜”等同于需要虚拟人，也不要把弱网与敏感数据混为一种部署需求。当前本地规则生成不是本地大模型，现有本机运行也不能直接称为完整离线 AI。

## 中国平台与网络：明确能力、授权和退路

国内发布能力应逐平台验收。抖音官方 `video.create` 文档说明需要权限和用户授权，代用户创建内容时应让用户明确感知；新版使用规范要求开发者通过控制台申请相应能力。不同页面对默认权限的描述有差异，应以实际应用类型、控制台状态与当前适用规范为准，不能仅凭一份文档承诺全量代发。[创建视频接口](https://open.douyin.com/platform/resource/docs/openapi/video-management/douyin/create/create-video)、[发布能力使用规范](https://partner.open-douyin.com/docs/resource/zh-CN/dop/operation-standard/platform-capabilities/useclue)

因此连接器应区分四种状态：未接入、导出交付、已授权但未验收、已验收。上传文件、创建草稿、提交发布、平台审核和真正可见必须分开记录。第一版提供明确的人工发布包即可创造协作价值。不要依赖共享 Cookie、绕过验证或伪装用户脚本维持核心收入。

模型、字体、素材和运行时不能在用户打开页面后临时依赖海外 CDN。建议在可分发许可范围内打包必需资源，安装期准备模型，运行时提供连接检测和可读错误。本轮调研没有测试各供应商在中国不同地区/运营商的连通性，也没有验证所有模型的数据存储位置；“兼容国内 API”不等于数据不会出境。

## 当前不做与商业验证顺序

暂不做通用 Agent 画布、面向客户的学习/面试中心、全网热点搬运、未经授权的自动群发、通用 CRM、完整视频剪辑器、模型训练平台，以及“保证爆款/保证获客”的评分。它们要么偏离交付工作，要么依赖尚未验证的授权、数据或收益。

建议先卖一个可验收的小范围试点：一个品牌、三种固定栏目、两个目标渠道、明确篇数与人工确认节点。服务内容包括一次品牌资料整理、流程配置和复盘；报价应把软件使用、模型额度与人工服务分开。当前缺客户渠道与成本数据，不能把任意月费称为市场公允价。

四周验证建议如下；数字是试验门槛，不是现有成绩：

1. 访谈 8～12 个符合定位的团队，让其中 3 个用自己的脱敏资料执行完整任务；先记录原有流程时间和真实退回原因。
2. 对每队至少 5 个相似任务比较从 brief 到获批的时间、返工轮次与交付差错。争取中位交付时间缩短 30%，同时不增加事实错误；样本小，只做早期判断。
3. 请至少 2 队为下一轮固定范围试点付费，并明确有人负责持续提供资料和审核。如果没有复用或不愿付费，先调整场景、资料准备或交付标准，暂停增加集成数量。
4. 有重复购买后，再决定正式套餐、平台连接器、队列/监控、客户支持和公网部署投入。强工作流应体现为少填信息、少返工、能追责和按时交付。
