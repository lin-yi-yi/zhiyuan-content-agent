# v0.5 Data Loop

`ai-content-agent` v0.5 adds a content judgment feedback loop: record a prediction before publishing, enter real platform metrics after publishing, then calibrate the next cycle from the gap.

This is still a content growth workbench. It does not auto-publish, manage social accounts, scrape private platform data, or bypass platform rules.

## Scope

In scope:

- Record pre-publish predictions for a draft and platform.
- Bind a prediction to a publish log.
- Mark predictions as settled after real metrics are entered.
- Include prediction snapshots and prediction errors in weekly reports.
- Show prediction input in `数据录入`.
- Show calibration summary in `7天复盘`.
- Keep the desktop UI restrained and Apple-like: neutral surface, system font, subtle borders, blue primary action.

Out of scope:

- Auto-publishing to Xiaohongshu, Douyin, or any external platform.
- Account login, cookie/session handling, or credential storage.
- Platform crawling and automated metric collection.
- Fully automated prediction model training.
- Multi-account, multi-tenant, or external customer data separation.

## Data Model

New table: `content_predictions`.

Important fields:

- `draft_id`: the generated content package being predicted.
- `publish_log_id`: optional binding to the actual publish record.
- `platform`: platform boundary, currently `xiaohongshu` or `douyin`.
- `predicted_views`, `predicted_likes`, `predicted_favorites`, `predicted_comments`, `predicted_shares`, `predicted_new_followers`: absolute predicted outcomes.
- `predicted_save_rate`, `predicted_like_rate`, `predicted_comment_rate`, `predicted_follow_conversion_rate`: normalized prediction rates.
- `confidence`: 0-100 judgment confidence.
- `rationale`: why this prediction was made.
- `risk_notes`: known uncertainty before publishing.
- `status`: `draft`, `locked`, or `settled`.

Updated table: `weekly_reports`.

New JSON columns:

- `angle_performance`
- `content_type_performance`
- `template_performance`
- `performance_summary`
- `prediction_calibration`

`init_db.py` includes lightweight migration helpers for older local MySQL tables.

## Flow

1. User creates or selects a draft.
2. User records pre-publish prediction in `数据录入`.
3. User creates a publish log.
4. Backend binds the latest unbound prediction for the same `draft_id` and `platform`.
5. User records real metrics after publishing.
6. Backend marks linked predictions as `settled`.
7. Weekly report compares prediction and actual metrics.
8. `7天复盘` shows average view error, high/low estimate bias, and top misses.

```text

```

## Calibration

Weekly reports calculate:

- `prediction_count`
- `avg_abs_view_error_rate`
- `view_bias`: `underestimated`, `overestimated`, `balanced`, or `none`
- `underestimated_count`
- `overestimated_count`
- `top_misses`

The current calibration is intentionally simple and transparent. It is good enough for a creator workflow because it answers:

- Did I usually overestimate or underestimate this week?
- Which content was most misjudged?
- Should I adjust title, cover, topic angle, or template assumptions next week?

## Next Steps

Recommended v0.5 follow-up:

1. Use historical publish logs to pre-fill prediction suggestions.
2. Add draft-level benchmark cards: similar topics, similar templates, similar content types.
3. Add a calibration note back into the draft or topic, so next generation can reuse learned patterns.
4. Add confidence tracking: high-confidence misses should be reviewed more aggressively than low-confidence misses.
5. Keep auto-publishing out of scope until the data loop is stable.
