# 多信源核验与知识入库

本轮目标是做出可演示的本地闭环：**发现 → 本人核验笔记 → 明确确认 → 入库 → 带引用回答 → 到期或撤销后排除**。它面向求职展示和个人试用，仍运行在单用户、单进程的本地工作台内。

## 从页面开始

1. 打开「信源台」，选择 AIHOT 或 GitHub Releases。GitHub 当前支持 LangChain、Dify、RAGFlow 三个固定项目。
2. 点击「创建核验笔记」，只带入标题、链接和可用版本信息。AIHOT 摘要不会自动成为知识正文。
3. 在「核验笔记」填写自己的正文、结论、支撑摘录、出处、适用版本，以及可选的到期时间。标明本人原创、已获得授权或仅作链接参考。
4. 保存后仍为待核验。检查实际来源，明确确认后，单独点击入库。仅作链接参考、缺少引用、已经过期的笔记不能入库。
5. 到「检索与评测」提问，检查采用的知识片段，以及关联笔记的版本、来源和结论引用。无模型凭证时可使用本地原文摘录；这不代表生成模型质量已经验证。
6. 在核验台撤销核验，再提出相同问题，关联资料应被排除。资料到期后也会被动态排除，无需等待后台定时任务。

核验笔记页的合成示例用于熟悉操作。它描述虚构系统，不能当作真实新闻。修改已经保存的正文需要创建新版本，再撤销旧版；不会悄悄改写已核验内容。

## 目前能证明什么

| 能力 | 实现与边界 |
| --- | --- |
| 两种外部信源 | AIHOT 发现资讯；GitHub 读取维护者发布元数据。没有全网爬虫，没有保存发布正文或附件。 |
| 结论与引用 | 每条笔记保存 claim、excerpt、source_url、可选段落定位；文档与回答引用能回到笔记。不会自动判断摘录是否真的支持结论。 |
| 人工确认 | 保存、核验、索引分为独立动作；记录核验历史。确认代表本机使用者的判断，不是第三方认证。 |
| 版本与时效 | 保存版本、来源发布时间、核验时间和到期时间；提前 7 天提示，过期后排除。时效由使用者设定，不自动检测外部页面变化。 |
| 撤销生效 | SQL 核验记录为权威；旧向量和旧元数据不能恢复批准。生成模型返回后再次检查状态，避免引用生成期间被撤销的资料。 |
| 有效资料召回 | 语义检索先按有效文档筛选，再按向量排序；避免大量失效资料挤占候选。 |
| 失败恢复 | 重复入库幂等；索引失败保留错误状态，可重试；删除知识文档同步笔记状态，再从核验台显式入库恢复。 |
| 普通上传资料 | 继续可检索，但明确显示未登记核验和时效，不自动升级为核验资料。 |

## 信源和使用边界

- [AIHOT 接入说明](aihot-source-integration.md)保留其官方 API、MCP 与商业使用授权边界。官方 MCP 配置已有，本轮没有新增代理转售接口。
- GitHub 仅调用固定仓库的[公开 Release API](https://docs.github.com/en/rest/releases/releases#list-releases)。发布元数据属于维护者一手信息，具体主张仍待核验；普通标签不一定是 Release。
- GitHub 匿名 API 通常受来源 IP 共用额度限制。连接器遵循缓存、条件请求和限流等待；参见[官方限流说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)和[最佳实践](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。无法访问时展示错误和重试时间，不伪造数据。
- 正文应是自己的核验笔记或已有许可的资料。公开仓库、打开链接、标注出处本身不代表拥有任意再分发权利；参见[GitHub 许可证说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。本系统记录声明，不替使用者完成授权审核。

## 复现验收

```sh
./scripts/check.sh
./scripts/start.sh
# 另一个终端运行；创建独立合成知识库并保留，便于查看报告。
.venv/bin/python scripts/evaluate_evidence.py
```

GitHub 与 AIHOT 在绑定本机的启动脚本中开启。直接运行服务器默认关闭，使用 `GITHUB_ENABLED`、`AIHOT_ENABLED` 设置；不用的来源可以关闭，不影响核验笔记和本地检索。

自动检查覆盖状态迁移、跨知识库范围、幂等、引用锚点、错误恢复、过期、撤销、索引期间并发、回答期间撤销以及真实临时 Qdrant 的有效资料筛选。语义合同测试使用合成向量；运行中的真实中文模型效果单独写入 [信源闭环评测](validation/evidence-evaluation.json)，不混为一谈。

## 求职演示建议

用 5 分钟展示：来源区别 → 一条笔记与引用 → 待核验无法入库 → 确认后检索回答 → 撤销后再次提问 → 打开评测失败样本。讲清楚为什么需要每个环节，比只展示聊天界面更有说服力。

当前完成的是本地功能闭环。账号与生产租户权限、计费、云端运维、商业信源授权、Obsidian 双向同步没有因此自动完成。面试应按实际验收范围介绍，也需要能独立解释、修改和排错。

本轮运行证据与限制见 [验收记录](validation/source-evidence-acceptance.md)。
